# Воспроизводимый CSV-пример

Это небольшой **синтетический** комплект для проверки импорта, расчёта и Excel без исходных файлов компании. Два SKU, два поставщика, два демонстрационных склада; история 23.08–22.09.2026, дата расчёта **23.09.2026**. Идентификаторы с ведущими нулями намеренные. Названия `ALA-DEMO` и `AST-DEMO` не подтверждают наличие данных реальных городских складов.

## Состав и контракт

CSV использует UTF-8, разделитель `,`, точку для дробей и даты `YYYY-MM-DD`. Все шесть основных файлов обязательны; для отсутствующих приходов/интервалов можно оставить только строку заголовка.

| Файл | Обязательные колонки | Дополнительные поля |
|---|---|---|
| `sales.csv` | `date,sku,warehouse,qty` | `name,category,client_id,order_id,unit` |
| `stock.csv` | `sku,warehouse,on_hand` | `as_of`; пустой остаток остаётся неизвестным |
| `in_transit.csv` | `sku,warehouse,qty,eta` | `source_as_of`; пустой ETA остаётся неизвестным |
| `suppliers.csv` | `supplier_id,name,lead_time_days,min_order_qty` | Один поставщик на идентификатор |
| `sku_suppliers.csv` | `sku,supplier_id,pack_size` | `min_order_qty`; одна связь на SKU |
| `stockouts.csv` | `sku,warehouse,start,end` | Явные включительные интервалы отсутствия |
| `catalog.csv` — необязательный | `sku,name,category,unit` | `supplier_sku` и описательные поля |

Идентификаторы сохраняются строками, включая нули и суффиксы. Неверные числа/даты, отсутствующие обязательные колонки, повторные ключи справочников, отрицательные MOQ и неположительная кратность отклоняются с указанием файла. Для единицы используется `catalog.unit`, либо явно заданная `sales.unit`. Противоречащие единицы одного SKU отклоняются. Если единицы нет в обоих источниках, она остаётся неизвестной: движок показывает предупреждение, сервер запрещает подтверждение такой строки. Метры и штуки из названия товара не угадываются.

`DATA_AS_OF` задаёт дату расчёта; исходные даты CSV при этом не переписываются. Без настройки используется следующий день после последней даты продажи. Для пустой истории дата должна быть задана явно. История и приходы после разрешённой временной границы не используются как доступные данные.

## Быстрая проверка расчёта и XLSX

После установки backend-зависимостей выполнить из `backend/`:

```bash
OPENAI_API_KEY='' DATA_SOURCE=csv DATA_DIR=data/sample_csv DATA_AS_OF=2026-09-23 ./.venv/bin/python - <<'PY'
from pathlib import Path
from app.data.adapter import get_data_source
from app.core.recommend import generate_recommendations
from app.core.export import to_excel_bytes

data = get_data_source().load()
result = generate_recommendations(data, explain=False, service_level=0.5, review_period_days=2)
for group in result.groups:
    for line in group.lines:
        print(line.sku, line.recommended_qty, line.unit, line.rationale.lost_demand_uplift)
output = Path('/tmp/umytpa-csv-sample.xlsx')
output.write_bytes(to_excel_bytes(result))
print(output)
PY
```

Ожидается `00123_ → 40 м`, компенсация **30 м**; `00007 → 10 шт`, компенсация **0**. Файл — черновик расчётного движка. Эта команда не имитирует вход в систему, сохранение пользовательского заказа или серверное утверждение.

Автоматическая проверка дополнительно читает готовый XLSX и проверяет единицы, ведущие нули, неизвестную единицу и явное подтверждение только допустимых строк:

```bash
OPENAI_API_KEY='' ./.venv/bin/python -m unittest tests.test_sample_sources -v
```

## Подключение к интерфейсу

Используйте обычную процедуру создания администратора и запуска из [README](../../README.md). Для **API и worker** задайте одинаковые настройки источника:

```text
DATA_SOURCE=csv
DATA_DIR=data/sample_csv
DATA_AS_OF=2026-09-23
OPENAI_API_KEY=
```

`DATA_DIR` разрешается от корня репозитория, даже если процессы запущены из `backend/`. Можно поместить настройки в локальный `backend/.env`. API и worker также должны использовать одну рабочую БД. Настройки периода проверки/сервиса в интерфейсе могут менять количества относительно контрольных значений выше.

## Ограничения

Пример не является выгрузкой 1С или подтверждением совместимости конкретной обработки импорта в 1С. Он использует дневные продажи; дополнительные месячные CSV/сезонность этот адаптер не читает. MOQ, сроки, единицы и периоды отсутствия заданы для демонстрации. Небольшой набор проверяет воспроизводимость поведения, а не точность прогноза или нагрузочную способность.
