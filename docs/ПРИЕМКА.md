# Матрица требований и приёмка

Источник требований — ТЗ, исходный кейс и принятый план внутреннего сервиса.
Таблица связывает поведение с проверками, а не заявляет прохождение ещё не
выполненных проверок. Перед вводом на сервере результаты фиксируются с
версией кода, настройками, датой и составом выгрузок.

| Требование | Реализация | Проверка | Ограничение |
|---|---|---|---|
| Расчёт по всем источникам, сезонность, рост | Dataset + расчёт по SKU×склад | `tests.validate_must_have`, `test_calculation` | Точность на отложенном периоде отдельно не измерена |
| Исключение разового опта | Документ/клиент/транзакция, сверка месячных итогов | `test_calculation`, Must-have | Клиентов в реальных файлах нет |
| Упущенный спрос | Компенсация только явных stockout-интервалов | `test_calculation`, Must-have | Месячный остаток не заменяет интервалы отсутствия |
| Реальные выгрузки 1С | Read-only импорт, даты/коды/качество | `RUN_REAL_EXCEL_TESTS=1 ... test_excel_import` | Исходные имена файлов и допущения в реестре |
| MOQ, дробная кратность, независимые склады | Серверная и клиентская валидация | `test_calculation`, `test_export`, `orderUtils.test.js` | Неизвестные ограничения показываются как допущение |
| Объяснение каждой строки | Числовая раскладка и опциональный LLM | Must-have, `test_service`, визуальная проверка | LLM выключен по умолчанию, fallback при сбое/бюджете |
| Личные аккаунты и доступ | Argon2id, серверные cookie-сессии, manager/admin | `test_service`, `qa/smoke_service.py` | Создание администратора только CLI, нет регистрации |
| CSRF, блокировка, истечение, лимиты входа | Серверные проверки изменяющих запросов | `test_service`, HTTP smoke | HTTPS проверяется на Linux-хосте |
| Постоянные заказы и журнал | SQLite WAL, решения отдельно от расчёта, события | `test_service`, HTTP smoke с перезапуском | Один сервер, локальный диск |
| Конфликт двух вкладок | revision/409 + сравнение в UI | `test_service`, тесты состояния, браузерный сценарий | Локальные несохранённые данные нельзя считать серверной копией |
| Правка снимает утверждение | Атомарное сохранение решения | `test_service`, HTTP smoke, тесты UI | Экспорт до подтверждённого сохранения блокируется |
| Очередь, отмена, идемпотентность | Постоянные задания, один worker, дочерний процесс | `test_service`, HTTP smoke | Таймаут 600 секунд; аварийный расчёт повторяется явно |
| Подлинный Excel сохранённой версии | Два листа, утверждённые/черновые строки | `test_export`, HTTP smoke проверяет ячейки | Не гарантируется готовая обработка загрузки во все конфигурации 1С |
| Защита клиента от плохих ответов | Проверка JSON, MIME/ZIP, safe errors/abort | `frontend/src/api.test.js`, тесты UI | Сбой сети требует видимой ошибки и повтора пользователя |
| Нулевые срочные строки и единицы | Риск сохраняется, итоги по единицам | `orderUtils.test.js`, реальный UI | Метры и штуки не складываются одним числом |
| Поиск, страницы, весь поставщик | Скрытые строки входят в групповое утверждение | Браузерный сценарий и тесты UI | Область действия подписана |
| Мобильная таблица и нижняя панель | Внутренний скролл, Escape/жест, focus trap/return | Браузер 320/375/768/1440 px, клавиатура, 200% | Сборка и unit-тесты не заменяют визуальную проверку |
| Локальные шрифты и дизайн | Golos Text/Caveat с лицензиями, CSS-токены | Production build; Network без Google Fonts | Примеры карт/автомобилей не функции продукта |
| Ежедневные копии и восстановление | Online SQLite backup, integrity check, 14 копий | `test_ops` (WAL, retention, restore, отказ при повреждении) | Вынос копий с сервера настраивает организация |

| Подготовка ML IEK | Отдельные scripts и отслеживаемые артефакты | 14 тестов scripts, повторный аудит источников | Нет обученной модели, новой географии или backtest |
| Linux без контейнеров | systemd API/worker/timer, nginx TLS | `qa/check_linux_deploy.py`, Linux acceptance | Синтаксис CI не доказывает запуск на целевом сервере |

## Автоматические команды

Из `backend` после установки `requirements-dev.txt`:

```bash
python -m unittest discover -s tests -v
python -m tests.validate_must_have
RUN_REAL_EXCEL_TESTS=1 python -m unittest tests.test_excel_import -v
```

Из корня — настоящий API, отдельный worker и временная БД, без изменения
пользователей/данных рабочей системы:

```bash
python qa/smoke_service.py
python qa/smoke_service.py --real-data
```

Из `frontend`: `npm ci`, `npm test`, `npm run lint`, `npm run build`.
На Linux с nginx/openssl/systemd-analyze: `python qa/check_linux_deploy.py`.
GitHub Actions настроен выполнять синтетические регрессии, тесты scripts, HTTP smoke, UI-проверки,
сборку и синтаксическую проверку развёртывания.

## Браузерная приёмка

1. Войти менеджером, открыть прямую ссылку на свой заказ и обновить страницу.
   Чужой заказ менеджеру недоступен; администратор видит оба.
2. Рассчитать заказ на реальных файлах, проверить дату, предупреждения,
   коды, склад и единицы. Сопоставить раскладку и обе вкладки Excel с UI.
3. Ввести промежуточное невалидное количество, убедиться в запрете экспорта;
   исправить, дождаться сохранения, утвердить, затем снова изменить.
4. Изменить один заказ в двух вкладках: вторая получает сравнение версий
   и сохраняет локальные значения до осознанного решения пользователя.
5. При активном поиске и другой странице утвердить поставщика; проверить
   подпись области действия и полный сохранённый результат.
6. Оборвать сеть при сохранении/экспорте и восстановить соединение. Не должно
   быть ложного «Сохранено» или HTML под расширением XLSX.
7. Повторить основные действия на 320/375/768/1440 px, при 200% масштабе,
   клавиатурой и с длинными наименованиями. Проверить панель, Escape,
   возврат фокуса и отсутствие горизонтального скролла всей страницы.

## Серверная приёмка

Установить комплект по [DEPLOY.md](DEPLOY.md), проверить доверенный HTTPS,
readiness при живом/остановленном worker, сохранность после перезапуска,
миграцию копии старой БД и восстановление в отдельную тестовую БД.
На Windows локально проверяются бизнес-сценарии и резервное копирование;
проверка реальных systemd/nginx выполняется только на Linux.

## Приёмка объединения main с сервисным интерфейсом

Текущая интеграция переносит обогащение EKT, объединённый справочник складов,
сохранение CSV-идентификаторов и исключение двух подтверждённых примечаний
из main, сохраняя auth/orders/jobs, автосохранение, версии и Linux-поставку.
Исторические числа 65 серверных, 31 модульного и 16 компонентных тестов выше
описывают прежний frontend; 61 backend и 14 scripts в аудите main относятся к
другой версии. Эти результаты нельзя считать новым общим прогоном.

Дополнительные обязательные сценарии:

1. Метаданные после входа содержат defaults/capabilities и product_categories;
   catalog_enrichment не раскрывает внутренние пути и сырые ошибки.
2. Новый расчёт с product_category проходит очередь с идемпотентностью,
   сохраняет фильтр/описания; числовая рекомендация того же SKU не меняется
   от одного включения справочника.
3. Исходные категория 1С, имя, артикул, единица и условия партии не подменяются
   карточкой. Пропуски и конфликты видны; все группы сохраняют несопоставленные SKU.
4. Старый сохранённый заказ без product-полей открывается и экспортируется.
   Новая карточка не применяется к нему задним числом.
5. После изменения/удаления JSON уже сохранённый заказ экспортирует прежние
   EKT-поля и группу; XLSX содержит 37 колонок и оба листа с правильной ревизией.
6. Фильтр складов включает месячные/остаточные/приходные ключи без дневных продаж,
   исключает пустые значения, сохраняет исходное написание, не добавляет города сайта.
7. Товары с реальными кодами 0/1 остаются, две служебные строки пути исключаются;
   ведущие нули CSV сохраняются. Полный каталог приложенных файлов — 3 907 SKU.
8. Новые блоки покрытия/характеристик проходят клавиатурную и адаптивную проверку;
   внешние ссылки разрешены только для допустимых HTTPS-карточек EKT.
9. Полный набор прежних проверок доступа, сохранения, конфликтов, worker и backup
   остаётся успешным; отдельные scripts-тесты запускаются из корня.

```bash
backend/.venv/bin/python -m unittest discover -s scripts -p 'test_*.py' -v
```
