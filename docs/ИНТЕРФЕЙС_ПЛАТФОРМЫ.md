# Интерфейс Umytpa — экраны, действия и адаптивность

**Статус: целевой контракт промышленной платформы с картой фактической реализации, 23.09.2026.** Интерфейс и сервис из `baitc/frontend` (`5a0ace2`) интегрированы: работают вход, две роли, история, задания, сохранение заказов с ревизиями, журнал и экспорт. При интеграции добавлены EKT-фильтр/описания/безопасные ссылки и карточки товарных строк до 767 px. Это ещё не реализация всех десяти целевых экранов и пяти ролей ниже.

Главный источник правил — [ТЗ платформы](ТЗ_платформы.md); визуальные токены — [Дизайн фронтенда](Дизайн_фронтенда.md); реализованный интерфейс и API — [ФРОНТЕНД.md](ФРОНТЕНД.md). При противоречии по правам, численности, статусам или составу выпуска применяется главное ТЗ. Этот документ уточняет пользовательский контракт.

## 0. Что уже работает и как связано с целевыми экранами

Текущие роли — `manager` и `admin`. Менеджер работает со своими заказами, администратор — также с заказами команды и учётными записями. Проверки выполняются сервером. Нет отдельного `procurement_lead`, `data_analyst` или `business_viewer`, назначения областей по организации/складам/поставщикам. Полномочия нынешнего `admin` шире целевой технической роли из раздела 1.

| Целевой раздел | Текущий экран / доступность | Что ещё нужно по контракту |
|---|---|---|
| `/login` | Форма при отсутствии сессии, независимо от hash; отдельного `#/login` нет | Согласованный корпоративный способ входа и целевые области прав |
| `/overview` | Отдельного обзора нет; вход ведёт в `#/orders` | Задачи по ролям, очередь согласования, сводка проблем |
| `/orders` | `#/orders`: свои / все по роли, работа/архив, серверная пагинация | Бизнес-статусы согласования и расширенные фильтры |
| `/orders/new` | `#/calculate`, восстановление задания через `?job=ID` | Аналитический preview, разделение результата на отдельные заказы поставщиков |
| `/orders/:id` | `#/orders/ID`: правки, автосохранение, revision, конфликт, аудит, Excel | Независимое согласование всей версии, причины правок, исторические утверждённые версии |
| `/catalog` | Отдельного каталога нет; данные EKT доступны в «Почему?» | Поиск всего каталога, условия поставщиков и редактирование по правам |
| `/data` | Только сведения об источнике, покрытии и ограничениях в расчёте/заказе | Загрузка, проверка и атомарная активация пакетов через UI |
| `/analytics` | Отдельного экрана нет; offline backtest выполняется скриптом | Интерактивные показатели, сравнимые периоды, разрешённые выгрузки |
| `/administration` | `#/users`: admin создаёт сотрудников, меняет роль/активность/пароль | Области прав, приглашения и полный экран эксплуатации |
| `/management` | Не реализован | Публикация разрешённых агрегированных снимков для наблюдателя |

Дополнительно реализован `#/account`: имя, роль, статус, выход. В текущей истории нет отдельного маршрута `#/history`: она находится в `#/orders`.

Существенные границы реализации:

- `approved` — **построчное решение пользователя, сохранённое на сервере**. Оно не является решением независимого руководителя. У автора заказа сейчас нет запрета самостоятельно отметить позицию; целевое разделение обязанностей ниже ещё нужно реализовать.
- Один сохранённый заказ содержит результат расчёта с несколькими группами поставщиков. Требование «один поставщик — один заказ» остаётся целевым.
- Состояния задания сейчас `queued / running / completed / failed / cancelled`. В целевом контракте используется `succeeded`; при переходе требуется явное согласование API-имени, а не ожидание уже существующего поля.
- Ревизия и журнал фиксируют сохранённые изменения и экспорт, но ещё не дают целевой истории неизменяемых утверждённых версий и отдельного рабочего/исторического экспорта по свежести.
- Корректные правки сохраняются автоматически примерно через секунду; незавершённое поле остаётся на открытой странице. 409 показывает сравнение и явный выбор разрешения конфликта. После перезагрузки восстанавливаются серверные решения.
- Фильтр EKT, покрытие, характеристики и безопасная ссылка уже доступны. Товары без описания не исключаются при выборе всех групп. До 767 px показаны 5 карточек поставщика на страницу с теми же полями; на большем экране — 20 строк. Пагинация реагирует на viewport, сохраняет доступ к ошибке и не сокращает итоги/выгрузку. Время событий — Алматы с видимой подписью.

**Разделы 1–14 ниже — целевые требования и критерии приёмки.** Наличие соответствующей строки в них не означает, что функция готова. Полный актуальный перечень проверок находится в [отчёте по критериям](ОТЧЁТ_ПО_КРИТЕРИЯМ.md); отдельный browser E2E и полная приёмка целевой платформы не равны друг другу.

## 1. Целевые пользователи и точка входа

| Роль | Начальный экран | Основная работа |
|---|---|---|
| `purchase_manager` — менеджер закупок | `/overview` | Рассчитать потребность, проверить строки, сохранить и отправить заказ руководителю |
| `procurement_lead` — руководитель закупок | `/overview` | Проверить очередь, утвердить версию либо вернуть с замечанием; открыть управленческий обзор |
| `data_analyst` — аналитик / ответственный за данные | `/data` | Проверить загрузку, конфликты, свежесть, справочники и пригодность данных |
| `admin` — администратор | `/administration` | Управлять доступом и техническим состоянием; роль сама по себе не даёт права согласовать заказ |
| `business_viewer` — наблюдатель компании / спонсора | `/management` | Смотреть разрешённые агрегаты реальных данных, ход закупок и ограничения |

Доступ ограничивается организацией, назначенными складами и поставщиками. Назначение роли наблюдателя не открывает все данные компании. Плановая численность и нагрузка зафиксированы в ТЗ как проектные допущения; это не сведения о действующем штате.

Оболочка показывает Umytpa, название организации, текущий раздел, пользователя/роль, доступ к профилю и выходу. Выбор роли пользователем не подменяет проверку прав на сервере. Меню содержит только доступные разделы; открытие прямой ссылки также проверяется сервером.

| `/overview` | Рабочий обзор | Продолжить свою задачу или открыть очередь согласований |

| `/catalog` | Товары и условия | Найти товар и проверить его учётные и справочные сведения |

Контекст каждого результата включает организацию, склады, период, версию исходного пакета, время обновления и ограничения. Фильтры фиксируются в URL там, где это безопасно; персональные данные и служебные ключи в URL не попадают. Возврат из карточки сохраняет фильтры, страницу и позицию списка. Изменение фильтра просмотра не меняет состав или версию заказа.

## 3. Вход `/login`

- **Кто и зачем:** все пользователи; получить доступ к своей организации и разрешённым разделам. Самостоятельная публичная регистрация для первой версии не требуется.
- **Показывается:** название продукта и организации, форма/кнопка корпоративного входа, ссылка на согласованный канал помощи, сообщение об истекшей сессии. Пароль, если выбран такой способ входа, поддерживает менеджер паролей и вставку.
- **Действие и результат:** после успешной проверки — начальный экран роли либо разрешённая исходная ссылка. Пользователь без назначенного доступа видит понятный отказ, без раскрытия данных чужой организации.
- **Состояния:** ожидание, ошибка входа без раскрытия существования учётной записи, недоступность сервера, отключённая учётная запись. Повторное нажатие во время запроса не создаёт новую операцию.
- **Мобильный вид:** одна колонка, подписи над полями, экранная клавиатура не перекрывает вход; никакой зависимости от hover.

## 4. Рабочий обзор `/overview`

- **Кто и зачем:** закупщик и руководитель; понять, что требует действия сегодня. Аналитику предоставляется переход сюда только при отдельном праве просмотра.
- **Показывается:** активная область складов; свежесть продаж/остатков/приходов; свои черновики, возвращённые заказы, очередь согласования; последние завершённые расчёты; критические ограничения. Каждый счётчик открывает список с тем же условием отбора.
- **Закупщик:** «Новый расчёт», «Продолжить черновик», «Исправить замечания». Руководитель: «Проверить очередь», «Открыть обзор руководителя». Кнопка «Новый расчёт» зависит от фактических полномочий, а не от видимости карточки.
- **Результат действия:** переход в существующий заказ либо создание задания расчёта. Простой просмотр не меняет статус.
- **Состояния:** первый запуск объясняет необходимые данные; отсутствие задач — нормальный результат; отсутствующий актуальный остаток показан как проблема, а не как нулевой дефицит. Старый снимок остаётся помеченным датой.
- **Мобильный вид:** сначала задачи пользователя, затем свежесть и показатели; карточки в одну колонку, по 3–5 ближайших задач и ссылка на полный список.

## 5. Реестр заказов `/orders`

- **Кто и зачем:** закупщик — свои заказы в разрешённой области; руководитель — заказы своей области согласования. Прочие роли получают только отдельно назначенный доступ. Наблюдателю детализация заказов не предоставляется.
- **Фильтры:** поиск по номеру, статус, поставщик, склад, ответственный, дата создания/изменения. Сортировка по последнему изменению; отдельное представление «На согласовании».
- **Показывается:** номер, поставщик, склады строк, версия, автор, статус, количество включённых позиций, объёмы отдельно по единицам, дата изменения, ограничения. Денежный итог доступен только при полном подтверждённом покрытии закупочными ценами, валютой и согласованной методике; иначе — «Нет полной оценки». Для текущего набора финансовые показатели выключены.
- **Действие и результат:** открыть карточку; для доступного черновика — продолжить работу. Массового утверждения разных заказов в первой версии нет. Пагинация серверная; общий счётчик учитывает фильтр, а не только текущую страницу.
- **Состояния:** нет заказов / нет совпадений / ошибка загрузки различаются. Неудачная загрузка следующей страницы не стирает уже показанный список.
- **Мобильный вид:** карточка заказа содержит поставщика, номер/версию, статус, ответственного, дату и явную кнопку открытия. Расширенные фильтры открываются отдельной панелью; число активных фильтров видно всегда.

## 6. Новый расчёт `/orders/new`

- **Кто и зачем:** закупщик и руководитель; сформировать воспроизводимые рекомендации. Аналитик может запустить проверочный расчёт без права создания и согласования заказов. Один расчёт может дать несколько заказов, **по одному поставщику на заказ**; склад сохраняется у каждой строки.
- **Показывается:** разрешённые склады и поставщики, категория 1С, товарная группа EKT, уровень сервиса, период проверки, доступная дата/версия исходных данных, подтверждённые сроки поставки, ограничения. Город отдельно от склада здесь не вводится.
- **Фильтр EKT:** указывается число сопоставленных товаров и неполное покрытие. «Все товарные группы» сохраняет товары без обогащения; конкретная группа отбирает только сопоставленные позиции.
- **Действие «Рассчитать»:** сервер закрепляет пакет и параметры, возвращает идентификатор задания. Состояния `queued / running / succeeded / failed / cancelled` отображаются как «В очереди / Считаем / Готово / Ошибка / Отменено»; показывается реальный этап, без вымышленного процента.
- **Результат:** список поставщиков, количество рекомендованных строк, ограничения и действие «Создать черновики» для закупщика/руководителя. Для аналитика доступны только результаты проверки. Повторное действие с тем же ключом операции не дублирует заказы. Автор выбирает нужных поставщиков, видит список создаваемых черновиков и после подтверждения открывает их в реестре.
- **Состояния:** некорректный период, пустая область, недостаточная история и отсутствие потребности различаются. Задание продолжается после ухода со страницы; результат доступен после повторного входа. Отмена подтверждается сервером; поздно завершившаяся отмена не создаёт заказы.
- **Мобильный вид:** параметры в одну колонку, блок ограничений до кнопки запуска; после запуска компактная карточка задания и возможность уйти в реестр. Исходные значения не теряются при раскрытии подсказки.

## 7. Карточка заказа `/orders/:id`

**Шапка:** номер, поставщик, автор, версия, статус, время последнего сохранения, исходный расчёт и пакет данных. Панель параметров показывает именно сохранённые значения. Новый расчёт создаёт новый результат/ревизию; не заменяет согласованный заказ молча.

Доступ к целому заказу требует прав на поставщика и все склады его строк. Частично скрытый заказ нельзя согласовать или выгрузить целиком: до отправки его разделяют по областям либо назначают согласующего с полным доступом. Создатель и все участники изменения состава/количеств, включая унаследованные правки, не могут утвердить эту версию; смена ответственного не снимает запрет.

**Строка на компьютере:** включение в заказ, SKU/артикул/название, склад, единица, срочность, покрытие в днях, рекомендованное количество, поле ручного количества, MOQ/кратность, значок ограничений, «Обоснование». Поле допускает корректные дробные количества для соответствующей единицы. Ноль исключает строку; пустая, отрицательная или некорректная величина блокирует отправку.

**Строка на телефоне:** сверху название и SKU, далее склад/единица/риск, рекомендовано и поле количества, правило партии, причина изменения и кнопка подробностей. Выбор «Включить в заказ» имеет постоянную подпись. Поля не скрываются за горизонтальным скроллом. Список поддерживает поиск, фильтр проблем и серверную пагинацию.

**Обоснование:** прогноз на горизонт, спрос в день, сезонность и тренд, страховой запас, учтённые остаток/дата и приходы, исключённый опт, доступность stockout-оценки, исходное и ручное количество, комментарий автора. Отдельно — категория 1С и описание EKT с датой/ссылкой. Отсутствие stockout-данных не трактуется как доказанное отсутствие дефицита.

### 7.1. Действия по состоянию

| Состояние | Закупщик | Руководитель |
|---|---|---|
| `draft` — Черновик | Изменить состав/количества, указать причину правок, сохранить, отправить, отменить | Со своим черновиком — действия автора; чужие смотреть в своей области, не подменяя авторские количества |
| `submitted` — На согласовании | Просматривать; отозвать с обязательной причиной в `cancelled` до принятия решения | Утвердить точную версию целиком либо вернуть с обязательным комментарием |
| `changes_requested` — Нужны правки | Прочитать замечание, создать редактируемую ревизию `draft`, исправить, отправить повторно; отменить | Просмотреть ранее оставленное замечание и историю |
| `approved` — Утверждён | Выгрузить утверждённую версию; для изменений создать новую черновую ревизию | Просмотреть решение и выгрузить в пределах полномочий |
| `cancelled` — Отменён | Просмотр и история; копирование в новый черновик с явной связью при необходимости | Просмотр и история; копирование в свой черновик при наличии прав |

Закупщик выбирает строки, но **не утверждает собственный заказ чекбоксом**. Руководитель может работать со своим черновиком как автор; согласовать его должен другой уполномоченный руководитель. Согласование относится ко всей точной версии заказа. Частичного согласования в первой версии нет: при необходимости автор заранее выделяет отдельный заказ. Разрешённые переходы и запрет согласования собственного заказа определяются главным ТЗ и проверяются сервером.

### 7.2. Сохранение, отправка и экспорт

1. Внесённые правки получают индикатор «Есть несохранённые изменения». «Сохранить черновик» записывает количества, включение строк и причины на сервер; только ответ сервера меняет индикатор на время сохранения. Уход со страницы с несохранённым содержимым требует выбора «Сохранить / Остаться / Уйти без сохранения».
2. Перед отправкой показываются поставщик, версия, включённые позиции, объёмы по единицам, критические проблемы и адресат согласования. Неизвестные идентификатор/единица не обходятся подтверждением. Иные исключения возможны только по политике главного ТЗ с ответственным и объяснением; закрытие предупреждения не является исключением.
3. Руководитель видит изменение относительно расчёта и предыдущей ревизии, причины, источники и замечания. «Утвердить версию N» и «Вернуть с комментарием» подтверждаются сервером и записываются в журнал. Новые правки не наследуют прежнее согласование.
4. Excel формируется по сохранённой версии, а не по текущим несохранённым полям. Перед экспортом несохранённых правок предлагается сохранить их. Файл черновика явно помечен «Черновик»; утверждённый — содержит сведения об утверждённой версии. Набор колонок и происхождение чисел определены главным ТЗ.
5. Экспорт — отдельное событие с автором, версией и временем. Надпись «Файл готов» появляется после получения файла; отказ браузера в скачивании предлагает повторить загрузку того же артефакта. Скачивание не означает отправку поставщику или создание документа 1С.

Рабочий Excel доступен для последней утверждённой версии без начатого пересмотра и с допустимыми данными её снимка. Для старой/устаревшей/пересматриваемой версии действие называется «Скачать историческую копию»; файл содержит заметную пометку «Историческая версия — не текущий заказ» и даты. Новый активный пакет не снимает устаревание прежнего расчёта. При недопустимой свежести рабочая выгрузка заблокирована, доступна историческая копия и переход к новому расчёту.

**Мобильная панель действий:** «Сохранить» и основное действие роли над нижней навигацией, второстепенные — в доступном меню. Утверждение не требует свайпа; перед ним доступно полное обоснование. Нижняя панель не скрывает последнюю карточку, ошибку или экранную клавиатуру.

## 8. Товары и условия `/catalog`

- **Кто и зачем:** закупщик/руководитель читают; ответственный за данные исправляет разрешённые сопоставления и подтверждает условия согласно журналируемому процессу.
- **Показывается:** поиск по SKU, артикулу, названию; поставщик, категория 1С, группа EKT, единица, MOQ/кратность, срок и статус его подтверждения, качество сопоставления. Карточка разделяет учётные данные, условия поставки и справочное описание сайта.
- **Действие и результат:** открыть товар, перейти к связанным расчётам в пределах доступа, зафиксировать проблему. Изменение справочника создаёт новую версию для будущих расчётов, не переписывает исторические заказы.
- **Состояния:** EKT не найден / неоднозначное совпадение / отсутствует MOQ или срок / неизвестная единица. Отсутствие описания само по себе не блокирует числовой расчёт; неизвестная единица влияет на допуск заказа.
- **Мобильный вид:** карточки с названием, кодом, единицей и статусом; вторичные поля раскрываются. Внешняя ссылка явно подписана и не заменяет проверку учётной идентичности.

## 9. Источники и качество `/data`

- **Кто и зачем:** аналитик проверяет и активирует данные; руководитель и закупщик читают сводку качества своей разрешённой области без доступа к сырым файлам. Ограничения также видны в обзоре, расчёте и заказе. Сырые файлы доступны только отдельному праву. Наблюдатель получает лишь опубликованное резюме в `/management`.
- **Показывается:** активный пакет, файлы/источники, область складов, даты отчётов и загрузки, объёмы, свежесть, исключённые строки, конфликты единиц/артикулов, пропуски остатков и условий. Каждая проблема имеет источник и путь исправления.
- **Процесс:** выбрать файлы утверждённого формата → загрузить в проверяемый пакет → увидеть отчёт и различия с активным пакетом → исправить/отклонить → активировать допущенный пакет. Действующая версия остаётся доступной до успешной активации; загрузка не запускает автоматическую замену заказов.
- **Действие и результат:** аналитик получает идентификатор проверки и отчёт; после активации новый расчёт использует новый пакет. Событие фиксирует пользователя, время и результаты проверки. Новая версия каталога EKT отображается отдельно от учётных данных.
- **Состояния:** загрузка, проверка, ошибки схемы, предупреждения, готовность, отклонение, ошибка активации. Повтор загрузки не активирует один пакет дважды. Доступный обход предупреждений определяется главным ТЗ.
- **Мобильный вид:** свежесть и критические проблемы первыми; поддерживаются выбор файла и просмотр отчёта, прогресс и явное повторение после сбоя. Большую загрузку нельзя считать завершённой при уходе браузера в фон.

## 10. Аналитика `/analytics`

- **Кто и зачем:** аналитик и руководитель — история спроса, состав рекомендаций и качество процесса; закупщик — показатели своей разрешённой области без доступа к сырым источникам. Для наблюдателя используется отдельный разрешённый управленческий снимок.
- **Показывается:** выбранные период/склад/поставщик, продажи по времени, доступные остатки, рекомендованные и ручные количества, причины правок, время согласования, покрытие данных. Графики имеют таблицу значений, единицы и метку пропуска.
- **Действие и результат:** сменить фильтр, открыть состав показателя, сравнить периоды одной области, выгрузить разрешённый аналитический срез. Сравниваемые периоды и полнота источников показаны явно.
- **Состояния:** короткая история, неизвестные нули, изменение состава складов, отсутствие цен/stockout, несопоставимые периоды. Точность прогноза показывается только после проверки на отложенных временных периодах; подготовленная таблица обучения не равна точности модели.
- **Мобильный вид:** один график за раз, подписи и текстовый вывод, выбор периода без сложного drag-жеста. Сложные сравнения допускают локальную таблицу с обозначенным скроллом и альтернативным списком.

## 11. Администрирование `/administration`

- **Кто и зачем:** администратор; выдать и отозвать доступ, настроить область и увидеть технические сбои. Наличие технической роли не даёт обхода правил заказа.
- **Показывается:** пользователи, активность, роли, организации/склады, состояние интеграций и фоновых заданий, журнал операций, версия приложения. Секреты не возвращаются в браузер; настройки показывают только состояние и маску.
- **Действие и результат:** пригласить/отключить пользователя, назначить роли и область, отозвать сессии, изменить согласованные настройки. Экран перед применением показывает кого и какие права затронет изменение; результат подтверждается сервером и журналом.
- **Состояния:** нет прав, конфликт одновременного изменения, истёкшее приглашение, недоступная интеграция. Нельзя убрать последнего действующего администратора без проверенной процедуры передачи доступа.
- **Мобильный вид:** список пользователей карточками, права отдельной формой; опасные операции требуют явного подтверждения с названием пользователя/области и не доступны случайным свайпом.

## 12. Обзор руководителя `/management`

**Кто и зачем:** руководитель закупок и `business_viewer`, включая разрешённого представителя спонсора. Это рабочий обзор реального предприятия. Внешнему наблюдателю передаётся проверенный, опубликованный руководителем агрегированный снимок с разрешённой областью, а не доступ ко всем первичным данным.

Порядок блоков помогает за одну минуту понять ситуацию:

1. **Область и актуальность:** организация, склады/поставщики, период, дата исходных данных, время формирования и публикации, ответственный. Если область ограничена, это написано в шапке.
2. **Состояние закупок:** число заказов по статусам, число включённых позиций, доля заказов с критическими ограничениями, медианное время согласования при наличии событий. Единицы, период и знаменатель присутствуют рядом с показателем.
3. **Что требует внимания:** устаревшие остатки, неподтверждённые условия, незавершённые проверки. Наблюдатель читает разрешённое резюме; руководитель по правам переходит к конкретным задачам.
4. **Подтверждённые результаты:** фактические значения за сопоставимые периоды, методика и ограничение интерпретации. Экономия, ROI, снижение дефицита и рост точности отсутствуют до появления проверяемой базы сравнения; вместо них — «Недостаточно данных для оценки» с причиной.
5. **Методика и ответственность:** что рассчитано, что согласовано человеком, какие источники использованы, контакт ответственного внутри организации. Контактная информация выводится только из разрешённого справочника.

**Действия:** выбрать доступный опубликованный период/область, раскрыть определение показателя; при отдельном разрешении скачать агрегированный PDF-отчёт опубликованного снимка с той же версией, датами и ограничениями. Выгрузка SKU, закупочных цен, сырой истории, изменение расчёта, согласование и настройки наблюдателю недоступны. Сервер отдаёт отдельную разрешённую проекцию, а не полный ответ со скрытыми в браузере полями.

**Публикация:** руководитель видит предварительный просмотр показателей, разрешённую аудиторию и перечень полей; подтверждает публикацию неизменяемой версии. Обновление учётного пакета не меняет опубликованный снимок. Отзыв публикации закрывает дальнейший просмотр/скачивание; ранее скачанный файл технически не отзывается. Журнал сохраняет автора, область и время публикации/отзыва.

**Состояния:** ещё ничего не опубликовано, недостаточно событий для показателя, снимок устарел, доступ отозван, нет разрешённой области. Пустое значение не заменяется красивым числом; устаревший снимок имеет заметную дату и предупреждение.

**Мобильный вид:** область/дата → 3–4 основных показателя → проблемы → методика. Карточки в одну колонку; графики и пояснения раскрываются кнопкой. Наблюдателю не приходится разбирать таблицу из десятков колонок или устанавливать отдельное приложение.

## 13. Общие состояния и защита работы пользователя

| Событие | Что видит пользователь | Обязательное поведение |
|---|---|---|
| Долгая операция | Этап, время начала, идентификатор, действие возврата | Не изображать окончание; после входа восстановить реальное состояние задания |
| Нет результатов | Причина: фильтр / нет потребности / нет данных | Разные тексты и подходящее действие; не показывать одну универсальную ошибку |
| Ошибка сервера | Понятное сообщение и код обращения | Сохранить введённые значения в памяти страницы, повторять только безопасным способом; не показывать traceback |
| Потеря сети | «Нет связи; изменения не сохранены» | Запретить отправку/утверждение/экспорт новой версии; не ставить финансовые операции в скрытую очередь |
| Истекла сессия | Вход и объяснение необходимости повторить действие | После входа получить права и актуальную версию; несохранённое содержимое не считать записанным |
| Конфликт версии, HTTP 409 | Кто/когда обновил заказ, сравнение моей и серверной версии | Предложить загрузить актуальную версию и явно перенести разрешённые правки; без тихого перезаписывания |
| Новые исходные данные | «Заказ рассчитан по пакету N; доступен M» | Сохранить старый результат; новый расчёт отдельной операцией с новым согласованием |
| Нет прав / удалённая ссылка | Доступ закрыт и переход в разрешённый раздел | Не отдавать закрытые поля в API; отсутствие кнопки не считается защитой |
| Двойное нажатие | Одна операция в работе | Ключ идемпотентности и серверная проверка версии; один заказ/одно согласование |
| Критическая проблема данных | Конкретные затронутые строки и причина блокировки | Исправление источника или только разрешённое документированное исключение; неизвестные SKU/единицы не обходятся |

Офлайн-редактирование с последующей автоматической синхронизацией не входит в первую версию. Данные, видимые до разрыва связи, помечены как последнее полученное состояние. Изменения остаются в памяти открытой страницы, но переживание перезагрузки для несохранённых данных не обещается; рабочие черновики должны своевременно сохраняться на сервере.

## 14. Приёмка интерфейса

Проверки выполняются с реальными разрешениями на сервере и сохранением после обновления страницы. Одних скриншотов или скрытия кнопок недостаточно.

| ID | Сценарий | Проверяемый результат |
|---|---|---|
| UI-01 | Закупщик входит и создаёт расчёт, уходит со страницы | Задание и результат доступны после повторного входа, параметры и пакет совпадают |
| UI-02 | Изменяет количество и включает строки, сохраняет, обновляет страницу | Правки и причины восстановлены; числовые правила проверены клиентом и сервером |
| UI-03 | Отправляет заказ, руководитель возвращает и согласует следующую ревизию | Согласованы точные версия/состав; автор, время и замечания сохранены |
| UI-04 | Два пользователя меняют один черновик | Второй конфликт получает сравнение; данные первого не теряются |
| UI-05 | Открывает неизвестную единицу или устаревший остаток | Видно влияние на заказ; действуют правила блокировок/исключений ТЗ |
| UI-06 | Экспортирует утверждённый заказ после нового пакета, устаревания или пересмотра | Excel относится к сохранённой версии; при устаревании/пересмотре доступна явно помеченная историческая копия; новый пакет не обновляет старое согласование |
| UI-07 | Наблюдатель открывает `/management` и прямую ссылку на заказ/API | Видит только разрешённый снимок; закрытые детали недоступны и через API |
| UI-08 | Наблюдатель читает обзор за минуту | Находит период, область, актуальность, статус закупок и ограничения; не принимает прогноз за достигнутую экономию |
| UI-09 | Основной сценарий при 320/360/390/768/1024/1440 px и 200% масштабе | Нет потери действий/значений, горизонтального скролла страницы, перекрытия фокуса/последней строки |
| UI-10 | Клавиатура, экранный диктор, уменьшение движения | Доступны подписи, статусы, ошибки, таблицы и все действия без hover/свайпа |
| UI-11 | Пропадает сеть при сохранении/утверждении/скачивании | Нет ложного успеха, дублей или скрытой отправки; повтор привязан к той же операции |
| UI-12 | Открывает склады и товары без обогащения EKT | Нет выдуманных региональных данных; расчёт по учётным товарам не требует описания сайта |

Поддержка мобильного браузера — часть приёмки промышленной версии. Установка нативного приложения, push-уведомления, автоматические письма поставщикам и запись заказа в 1С в этот контракт первой версии не входят. Возможные расширения оформляются отдельно после работающего процесса закупок.
