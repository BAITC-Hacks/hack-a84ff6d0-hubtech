# Бэкенд — спецификация

Сервис расчёта рекомендованных заказов поставщикам. FastAPI + движок на pandas/numpy/scipy.

---

## 1. Стек и структура

- **FastAPI** (`app.main:app`) + **uvicorn**, CORS открыт для дев-фронта.
- **pydantic v2** — контракты запросов/ответов (`app/schemas.py`).
- **pandas / numpy / scipy** — обработка данных, линейный прогноз и квантиль для страхового запаса. `statsmodels` присутствует в зависимостях, но текущий прогноз его не использует.
- **openpyxl** — чтение выгрузок 1С и экспорт заказа.
- **openai** — обоснования (опционально; есть офлайн-фолбэк).

```
app/
  main.py         приложение, CORS, подключение роутера с префиксом /api
  config.py       Settings из окружения/.env (кешируется lru_cache)
  schemas.py      Pydantic-модели
  api/routes.py   эндпоинты
  core/           движок (см. раздел 5)
  data/           источники данных (см. БД-раздел и ML_И_ДАННЫЕ.md)
```

## 2. Модули движка (`app/core`)

### `outliers.py` — исключение разового опта (MH#4)
Объединяет строки по документу либо клиенту/дню. Требует минимум пять положительных наблюдений и одновременно превышение `Q3 + 3·IQR` и ≥ 8× медианы. Правила доли 40% нет. Возвращает очищенные транзакции и кандидатов для сверки с месячными итогами.

### `stockout.py` — компенсация упущенного спроса (MH#3)
Работает в дневной ветке с явно переданными периодами по SKU/складу. Оценивает спрос по здоровым дням той же недели/месяца, сохраняет более высокий факт; uplift равен только добавке. В месячной ветке не вызывается; в реальных выгрузках периоды отсутствуют.

### `forecasting.py` — прогноз (MH#2)
Отдельные дневной и месячный пути. Дневной уровень — последние 90 дней, тренд — недельные средние на последних 180 днях; месячные уровень/тренд — последние 3/6 месяцев. Линейный тренд оценивается после десезонализации по реальным датам. Месячная σ — оценка по Пуассону и межмесячному разбросу, ежедневные наблюдения не выдумываются. Подробности: [ML_И_ДАННЫЕ.md](ML_И_ДАННЫЕ.md).

### `replenishment.py` — потребность (MH#1)
Точка заказа с покрытием на горизонт `H = срок поставки + период проверки`:
```
потребность = прогноз(H) + страховой_запас − остаток − товары_в_пути
страховой_запас = z(уровень сервиса) · σ · √H
```
Сначала подъём положительной потребности до MOQ, затем округление до кратности, включая дробные партии. Покрытие учитывает последовательность ETA и возможный дефицит до прихода.

### `recommend.py` — оркестратор (MH#5)
Связывает шаги по каждому `(sku, warehouse)`, использует **месячные итоги как выбранный основной источник количества** со сверкой против транзакций, группирует по поставщикам, добавляет `Rationale` + обоснование. Возвращает `RecommendationResponse`.

### `explain.py` — обоснование
LLM-текст (OpenAI API) на основе раскладки; при отсутствии ключа/сбое — детерминированный шаблон. Сбой LLM не роняет расчёт.

### `export.py` / `snapshots.py`
`snapshots` хранит результат расчёта по `calculation_id`; `export` формирует Excel (черновой или только утверждённые строки).

## 3. REST API (полный перечень)

Базовый префикс — `/api`.

### Служебные
| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | Проверка живости (`{"status":"ok"}`) |
| GET | `/api/meta` | Справочники для UI: склады, категории, поставщики, `sku_count`, `data_source`, `as_of`, `warnings`, `data_quality`, `product_categories`, `data_quality.catalog_enrichment` |

### Расчёт и экспорт
| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| POST | `/api/recommend` | `RecommendRequest` | `RecommendationResponse` (+ `calculation_id`) |
| POST | `/api/recommend/export` | `ExportRequest` | `Excel (.xlsx)` — `approved_order.xlsx` / `order_draft.xlsx` |

**`RecommendRequest`:** `warehouse?`, `category?` (внутренняя), `product_category?` (каталог сайта), `service_level?` (0.5–0.999), `review_period_days?` (1–120), `explain` (bool).
**`ExportRequest`:** `calculation_id`, `approved_only`, `lines: [{line_id, quantity, approved}]` по всем строкам снимка. Экспорт не пересчитывает прогноз и не отправляет документ в 1С.

Коды ошибок: `422` — не удалось прочитать источник/невалидный экспорт; `410` — snapshot расчёта устарел (нужно пересчитать).

## 5. Сервисный слой: как считаются метрики (честно)

- **Основной источник количества — месячные матрицы 1С до сверки их области с партнёром.** Транзакции берутся для выявления опта; если сумма транзакций месяца расходится с месячным итогом, крупные заказы в несогласованных месяцах не вычитаются (чтобы не стереть реальный спрос), и это попадает в `warnings`.
- **Полуоткрытые окна `[as_of, as_of+H)`** едины для прогноза и ETA товаров в пути.
- **Незавершённый месяц** не сравнивается с полным (обрезается по `complete_month_cutoff`).
- **Остаток:** приоритет — снимок «свободный остаток» из файла «Путь …»; фолбэк — последний известный начальный остаток месяца (помечается как устаревший).
- **Срочность:** `high` — покрытие < срока поставки; `medium` — < горизонта; иначе `low`.

## 6. Особенности реализации (честно)

- Формулы Excel читаются по **сохранённым значениям** (`data_only=True`), внешние ссылки не обновляются.
- `sheet.reset_dimensions()` — партнёрские файлы содержат устаревшие записи размеров листа.
- Импорт кешируется по fingerprint (путь + mtime + размер); фильтры UI работают на `deepcopy`, чтобы не мутировать кеш.
- Таблицы заранее группируются по SKU/складу, чтобы не сканировать всю историю для каждого товара. Время расчёта зависит от оборудования и данных; ожидание ответа нужно учитывать в прокси.

## 9. Обогащение каталога и граница с 1С

Локальный `data/ekt/catalog.json` версии 1 добавляет товарные поля без сетевого запроса во время расчёта/экспорта. Настройки: `EKT_CATALOG_ENABLED`, `EKT_CATALOG_PATH`. Связь только по точному `sku`, конфликтующие и дублирующиеся записи не объединяются. Внутренняя категория 1С сохраняется; `product_category` — самостоятельный фильтр. Описательные поля не меняют числовой спрос.

`/api/meta` возвращает `product_categories` и `data_quality.catalog_enrichment`; строки рекомендаций содержат доступные `product_*` поля и дату получения описаний. Подробный контракт — [КАТАЛОГ_EKT.md](КАТАЛОГ_EKT.md).

Установленная 1С не нужна для файлового прототипа. Прямого коннектора и обратной записи заказа пока нет; контракт CSV/Excel и варианты будущего чтения изложены в [ИНТЕГРАЦИЯ_1С.md](ИНТЕГРАЦИЯ_1С.md).
