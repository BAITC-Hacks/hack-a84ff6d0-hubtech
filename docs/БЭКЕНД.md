# Бэкенд внутреннего сервиса

FastAPI, Python 3.12, pydantic v2; расчётный движок pandas/numpy/scipy/statsmodels
сохранён. Прямые зависимости находятся в `backend/requirements.txt`, полный
зафиксированный набор — в `requirements.lock`. Источники Excel/CSV/synthetic
адаптируются в единый `Dataset`; методология — [SOLUTION.md](../SOLUTION.md).

## Доступ и хранение

- Роли `manager` и `admin`: менеджер читает/правит свои заказы, администратор
  все заказы и сотрудников. Своего этапа согласования у администратора нет.
- Пароли Argon2id; первый администратор создаётся `python -m app.manage
  create-admin --username admin` со скрытым вводом пароля. Саморегистрации нет.
- Сессии в SQLite, cookie HttpOnly/Secure/SameSite; срок восемь часов.
  `APP_ENV=development` — явное исключение для локального HTTP.
- CSRF-токен выдаётся при входе/чтении сессии и передаётся в `X-CSRF-Token`
  при изменении данных. Попытки входа ограничены; блокировка сотрудника
  завершает его сессии. В ответах нет паролей, хешей и путей источников.
- SQLite использует WAL, внешние ключи, короткие транзакции и миграции по
  `PRAGMA user_version`. Путь: `APP_DB_PATH`, затем совместимый `ORDER_DB_PATH`,
  затем `backend/.cache/orders.sqlite3`.
- Исходный расчёт неизменяем; решения, версия и события хранятся отдельно.
  Изменение количества атомарно снимает утверждение. Несовпадение `revision`
  даёт `409`. Сохранённые заказы не очищаются по возрасту/количеству.
- Старые снимки импортируются в архив администратора; фиктивная история
  прежних действий не создаётся. Копии и восстановление — `app.ops`,
  см. [DEPLOY.md](DEPLOY.md).

## HTTP API

Кроме входа, health и readiness, endpoints требуют авторизации. Изменяющие
операции после входа требуют CSRF. Авторство и доступ проверяются сервером.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | Живость API |
| GET | `/api/ready` | Доступность БД и свежего heartbeat worker, 200/503 |
| POST | `/api/auth/login` | `{username,password}` → `{user,csrf_token}` и cookie |
| GET | `/api/auth/session` | Текущий пользователь и CSRF-токен |
| POST | `/api/auth/logout` | Завершить сессию |
| GET/POST | `/api/users` | Список / создание сотрудника, только admin |
| PATCH | `/api/users/{id}` | Роль, активность или новый пароль |
| GET | `/api/meta` | Склады, категории, поставщики, дата/качество источников, defaults/capabilities |
| POST | `/api/recommend` | Создать расчёт; с `Prefer: respond-async` → `202 {job_id,status}` |
| GET | `/api/jobs` | Доступные задания, включая незавершённые после обновления страницы |
| GET | `/api/jobs/{id}` | Состояние задания, `order_id` после завершения |
| POST | `/api/jobs/{id}/cancel` | Отмена задания |
| GET | `/api/orders` | История: `offset`, `limit`, `archived`; `{items,total}` |
| GET | `/api/orders/{id}` | Расчёт, решения и текущая версия заказа |
| PUT | `/api/orders/{id}` | Сохранить `{revision,lines}` |
| PATCH | `/api/orders/{id}` | Заголовок/архивирование `{revision,title?,archived?}` |
| GET | `/api/orders/{id}/events` | Кто, когда и что изменил/выгрузил |
| POST | `/api/orders/{id}/export` | `{revision,approved_only}` → Excel сохранённого заказа |
| POST | `/api/recommend/export` | Совместимый экспорт по `calculation_id`, с проверкой владельца |

Поля расчётных контрактов сохранены: `warehouse?`, `category?`,
`service_level?` (0.5–0.999), `review_period_days?` (1–120), `explain`.
Обычный `POST /api/recommend` без async-заголовка ждёт ту же очередь и
возвращает прежний `RecommendationResponse` с `calculation_id`.
`Idempotency-Key` позволяет повторно получить то же задание; другой запрос
с тем же ключом отклоняется. Не повторяйте изменяющие запросы с новым ключом
при неизвестном результате первого запроса.

Заказ содержит `id`, `owner_id`, `title`, `revision`, `archived`, даты,
`calculation` и `decisions`. Каждое решение — `{line_id,quantity,approved}`.
Сохранение передаёт все строки текущего расчёта: нельзя вводить чужие SKU,
дубликаты, недопустимое число или нарушать MOQ/кратность. Ноль допустим для
исключения позиции. При изменении количества одновременно переданное
утверждение не обходится сервером: сначала нужно сохранить новое количество.

Коды ошибок: `401` — сессия, `403` — права/CSRF, `404` — недоступный объект,
`409` — конфликт версии/операции, `422` — неверные данные/экспорт,
`429` — лимит входа/очереди. Внутренние ошибки не раскрывают пути и traceback.

## Очередь и объяснения

`python -m app.worker` выполняет по одному заданию из постоянной SQLite-
очереди. Состояния: `queued`, `running`, `completed`, `failed`, `cancelled`.
Расчёт ограничен 600 секундами; дочерний процесс можно завершить при отмене
или таймауте. Прерванные задания после аварии не выдают старый результат
за новый: получают ошибку и требуют явного повторного запуска.
Heartbeat проверяется readiness; HTTP-запрос не выполняет тяжёлый расчёт.

LLM по умолчанию выключен. При включении действует timeout обращения и
общий бюджет 120 секунд; отсутствие ключа/сбой/исчерпание бюджета возвращают
числовой шаблон. Ключ и обращения остаются на сервере.

## Экспорт и данные

Excel содержит заказ и лист параметров/допущений: коды 1С, артикулы
поставщиков, склады, единицы, исходную рекомендацию, решение менеджера и
утверждение. Экспорт сверяет `revision` и записывает событие, не пересчитывает
прогноз. «Черновик» включает положительные валидные количества, режим
«Только утверждённые» — положительные утверждённые строки.

Исходники читаются read-only по сохранённым значениям формул. Месячные
итоги определяют объём; транзакции выявляют опт. Расчёт идёт по SKU×склад;
горизонт прогноза и ETA общий, полуоткрытый. Недатированные, просроченные
или поздние приходы не уменьшают заказ. Старые/неизвестные остатки и отсутствие
интервалов stockout показаны явно. Подробности — [ML_И_ДАННЫЕ.md](ML_И_ДАННЫЕ.md).
