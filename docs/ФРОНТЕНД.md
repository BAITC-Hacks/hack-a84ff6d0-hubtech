# Фронтенд — реализованный интерфейс Umytpa

Интерфейс перенесён из `baitc/frontend`, коммит `5a0ace2` (`Merge completed Umytpa service into frontend`). Он включает оформление ветки и страницы, связанные с авторизованным сервисом. При интеграции восстановлены фильтр и описания EKT, проверка внешних ссылок и карточки товарных строк для телефона.

**Реально доступны две роли — `manager` и `admin`.** Есть вход, реестр заказов, фоновые расчёты, серверное сохранение правок, ревизии, журнал действий и экспорт. Отметка `approved` — сохранённое решение пользователя по позиции; независимого согласования всей версии руководителем ещё нет. Пять ролей, десять разделов и полный процесс — целевые требования [ТЗ](ТЗ_платформы.md) и [контракта интерфейса](ИНТЕРФЕЙС_ПЛАТФОРМЫ.md).

## 1. Стек и компоненты

React 19, Vite 8, нативный `fetch`, Node.js **22.19+ в ветке 22.x или 24.x**; зависимости фиксируются `package-lock.json`. Golos Text Variable и Caveat Variable поставляются локальными npm-пакетами, лицензии — в `frontend/public/licenses/`. Внешний сервис шрифтов при работе не нужен.

| Код | Ответственность |
|---|---|
| `src/App.jsx` | Сессия, оболочка, hash-навигация, повторный вход |
| `src/pages/` | Вход, реестр, расчёт/задания, заказ, команда |
| `src/hooks/useOrderEditor.js` | Автосохранение, последовательная отправка правок, конфликт ревизий |
| `src/orderState.js` | Сохраняемые решения, сравнение и перенос локальных правок |
| `src/api.js` | Cookie-сессия, CSRF, валидация ответов, таймауты, скачивание XLSX |
| `src/orderUtils.js`, `src/format.js` | Количества, итоги по единицам, безопасные ссылки, форматирование |
| `src/components/` | Поставщики, обоснование, источник/ограничения, состояния и ErrorBoundary |
| `src/index.css`, `src/App.css` | Реальные токены, оформление и адаптивность |

Vite проксирует `/api` на `http://127.0.0.1:8017`; для локальной проверки адрес меняется через `API_PROXY_TARGET`. Production-схема — в [DEPLOY.md](DEPLOY.md).

## 2. Реальные экраны и права

| Адрес / состояние | Назначение |
|---|---|
| Нет сессии | Вход по имени/паролю независимо от hash; отдельного `#/login` нет |
| `#/orders` | Свои заказы менеджера / все заказы администратора, «В работе / Архив», серверная пагинация по 20 |
| `#/calculate` | Параметры, источники/ограничения, последние задания |
| `#/calculate?job=ID` | Состояние задания, отмена, переход к результату |
| `#/orders/ID` | Сохранённый расчёт, правки, ревизия, обоснования, экспорт, журнал |
| `#/users` | Только admin: создание сотрудника, роль, включение/отключение, новый пароль |
| `#/account` | Имя, роль, статус, выход; пароль меняет администратор |

Сервер проверяет владельца: менеджеру доступен собственный заказ, администратору — также заказы команды. Скрытие кнопки не заменяет эту проверку. Разграничение по организациям, складам/поставщикам и отдельные роли руководителя, аналитика, наблюдателя пока не реализованы. Нынешний `admin` может работать с заказами, что отличается от целевой технической роли ТЗ.

Один сохранённый заказ сейчас содержит группы нескольких поставщиков. Правило целевой платформы «один поставщик на отдельный заказ» ещё требует реализации.

## 3. Расчёт

Параметры: склад, категория 1С, группа EKT, сервис 90/95/98/99%, целый период проверки 1–120 дней. AI-обоснования по умолчанию выключены, переключатель зависит от возможности сервера. Шаблонные объяснения и числовая раскладка работают без LLM.

`POST /api/recommend` отправляет `Prefer: respond-async` и ключ идемпотентности. После неопределённого сбоя повтор тех же параметров на открытой странице сохраняет ключ. Hash содержит ID задания; незавершённое состояние опрашивается примерно каждые две секунды.

Состояния текущего API: `queued / running / completed / failed / cancelled`. Процент выполнения не выдумывается. После завершения сервис уже сохранил заказ; его открывают по `order_id`. Отмена подтверждается сервером, уход со страницы сам по себе задание не отменяет.

## 4. Редактор и сохранение

Показаны владелец, название, даты, `revision`; доступны переименование, архив и восстановление. Поиск ищет код 1С, артикул поставщика, название, склад и сведения EKT. Фильтры просмотра — поставщик и срочность. Пагинация группы — **5 позиций при ширине до 767 px, 20 на большем экране**; размер страницы реагирует на изменение viewport через `matchMedia`. Итоги и решение по поставщику учитывают все его позиции, не только текущую страницу. При смене размера сохраняется страница с текущей опорной позицией; переход к ошибке использует актуальный размер страницы.

Корректные правки автоматически сохраняются после примерно одной секунды без нового ввода. «Сохранено» появляется после ответа сервера. Изменение количества снимает отметку строки на клиенте и сервере. Повторная отметка сначала сохраняет количество, затем решение. Ноль исключает позицию из выгрузки.

Пустое/отрицательное/нечисловое значение, нарушение MOQ или кратности показывают ошибку. Незавершённое поле остаётся в памяти страницы; при сохранении остальных правок сервер получает его последнее корректное количество. «К первой ошибке» снимает фильтры и открывает нужную страницу группы.

HTTP 409 загружает актуальную серверную версию и показывает различия. Пользователь выбирает её либо явно переносит свои изменённые поля. Тихого перезаписывания нет, перенос нового количества снимает отметку. При переходе/выходе есть сохранение или предупреждение; `beforeunload` предупреждает о незавершённой работе.

При истечении сессии редактор сохраняется скрытым в памяти. Вход тем же пользователем продолжает работу, другая учётная запись получает своё пространство. После закрытия/перезагрузки восстанавливаются только серверные решения; сохранность незавершённого ввода не обещается.

## 5. Экспорт и журнал

«Черновик Excel» и «Утверждённые» используют `POST /api/orders/ID/export` с ID, актуальной ревизией и режимом отбора. Прогноз не пересчитывается. Выгружаются все подходящие строки, включая скрытые поиском/страницами; нулевые исключены. Несохранённые/ошибочные значения и конфликт блокируют действие.

Клиент проверяет MIME и ZIP-сигнатуру XLSX. Подготовленный файл не означает отправку поставщику или документ 1С. Журнал фиксирует экспорт с ревизией, создание, правки количества/отметок, названия/архива, автора и время. Ревизия и журнал не заменяют согласование неизменяемой версии отдельным руководителем.

## 6. EKT, источники и география

`DataInfo` показывает `excel/csv/synthetic`, дату, предупреждения, покрытие сопоставления и дату справочника. Категория 1С и группа EKT раздельны; конкретная группа оставляет сопоставленные товары, все группы сохраняют позиции без описания сайта.

«Почему?» показывает прогноз, дневной спрос, сезонность, тренд, горизонт, страховой запас, датированный остаток, учтённый/неучтённый путь, потребность до округления, stockout, исключённый опт, MOQ/кратность. В справочной части — категория учёта, группа/подгруппа EKT, бренд, характеристики, дата и проверенная ссылка. Отсутствие описания явно обозначено.

Ссылка разрешена только для `https://ekt.kz` без чужого хоста, учётных данных или нестандартного порта, с `noopener noreferrer`. Браузер не парсит сайт при расчёте. EKT не подтверждает запас, закупочную цену или срок: [КАТАЛОГ_EKT.md](КАТАЛОГ_EKT.md).

Склады приходят из `/api/meta`, реальная область сейчас — Алматы. Города сайта не подменяют склады: [ГОРОДА_И_СКЛАДЫ.md](ГОРОДА_И_СКЛАДЫ.md). CSV `alish` и offline backtest не являются подключённой обученной моделью.

## 7. API и надёжность

| Назначение | API |
|---|---|
| Сессия | `/api/auth/session`, `/api/auth/login`, `/api/auth/logout` |
| Справочники / расчёт | `/api/meta`, `/api/recommend` |
| Задания | `/api/jobs`, `/api/jobs/ID`, `/api/jobs/ID/cancel` |
| Заказы / журнал | `/api/orders`, `/api/orders/ID`, `/api/orders/ID/events`, `/api/orders/ID/export` |
| Команда | `/api/users`, `/api/users/ID` |

Same-origin HttpOnly cookie хранит сессию; CSRF-токен находится в памяти и передаётся при изменениях. Пароли/ключи не сохраняются в localStorage. Ответы JSON проверяются по типам, ID, состояниям и соответствию решений строкам снимка.

HTML, traceback и внутренние пути не показываются. Есть сообщения 401/403/409/410/429. Таймауты: обычный запрос 30 с, metadata 120 с, файл 60 с. GET при сетевом сбое повторяется максимум один раз; изменения автоматически не повторяются. Есть ErrorBoundary, `role=status` и `role=alert`.

## 8. Оформление и адаптивность

Тёмная оболочка, верхняя навигация, светлые панели, лаймовые действия, Golos Text и акцент Caveat — фактический дизайн из ветки: [Дизайн_фронтенда.md](Дизайн_фронтенда.md).

При ширине **до 767 px** те же строки становятся карточками с кодом, названием/складом/единицей, срочностью, покрытием, количеством, отметкой и «Почему?». Второй набор полей не создаётся. Количество — 16 px; поле и область чекбокса — 44 px. Формы и навигация перестраиваются, обоснование становится нижней панелью с кнопками, Escape и дополнительным жестом закрытия.

Есть видимый фокус, пропуск навигации, подписи, возврат фокуса и `prefers-reduced-motion`. Время событий форматируется в `Asia/Almaty` с видимой подписью «Алматы»; дата без времени не превращается в вымышленное время события. Полная проверка 320/360/390/768/1024/1440 px, 200% масштаба и экранного диктора остаётся отдельной приёмкой.

## 9. Проверки и границы

Из `frontend/`:

```bash
npm ci
npm run test:unit
npm run test:ui
npm run lint
npm run build
npx playwright install chromium
PYTHON=/absolute/path/to/python npm run test:e2e
PYTHON=/absolute/path/to/python npm run test:e2e -- --real-data
```

Для E2E указывается Python с backend-зависимостями. Unit-тесты проверяют API, количество, экспорт и состояния; компонентные — сессию, роли, задания, конфликты и ошибки. Browser E2E — отдельный реальный браузер. Команды проверки не означают успешный прогон; его результаты фиксируются в [отчёте по критериям](ОТЧЁТ_ПО_КРИТЕРИЯМ.md).

Остаются целевые роли и области прав, независимое согласование версии, причины изменений, отдельные заказы поставщиков, каталог, загрузка проверяемых пакетов, аналитика и опубликованные управленческие сводки. Новый UI и серверное сохранение закрывают часть прежних пробелов, но не весь контракт.
