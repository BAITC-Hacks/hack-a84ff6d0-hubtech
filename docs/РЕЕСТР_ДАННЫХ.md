# Реестр данных, качество и воспроизводимость

Реестр первичных файлов партнёра, дополнительных справочников и производных артефактов. Количества ниже относятся к зафиксированным входам, а не к любому будущему импорту. Пользователи, заказы и решения после интеграции frontend-ветки хранятся отдельно в SQLite; это не новый источник спроса.

---

## 1. Зачем это нужно

Расчёт опирается на реальные выгрузки 1С. Чтобы результат был воспроизводим и проверяем, зафиксированы: перечень файлов, как они читаются, какие допущения приняты и как обновлять данные перед новым заказом.

---

## 2. Реестр выгрузок

Папки `IEK/` и `Systeme electric/` — по 6 файлов каждая (маппинг в `app/data/excel.py::SUPPLIER_FILES`):

| Тип | IEK | Systeme Electric |
|---|---|---|
| Продажи (транзакции) | `Динамика продаж_2025-2026.xlsx` | `Динамика продаж_Syseme Electric_2025-2026.xlsx` |
| Месячные продажи | `Ежемесячные продажи … 2 года.xlsx` | `Ежемесячные продажи … SystemElectric 2024-2026.xlsx` |
| Месячные остатки | `Ежемесячные остатки … ИЭК.xlsx` | `Ежемесячные остатки SystemElectric 2024-2026.xlsx` |
| MOQ / кратность | `MOQ  ИЭК.xlsx` | `MOQ SystemElectric.xlsx` |
| Товары в пути | `Путь ИЭК 22.09.2026.xlsx` | `Товар в пути_SystemElectric на 22.09.2026.xlsx` |
| Сезонность | `Сезонность ИЭК.xlsx` | `Сезонность SystemElectric 2024-2026.xlsx` |

Дата снимка остатков/пути берётся из имени файла (`…22.09.2026…`).

## 4. Качество данных и допущения (`Dataset.warnings`)

Ключевые (полный список — в ответе `/api/meta`):
- Клиентов в выгрузках нет → опт определяется по реальным документам/транзакциям, без объединения по клиенту.
- Точных интервалов stockout в партнёрских Excel нет → скрытый спрос из месячных остатков не выдумывается. Дневной и месячный методы компенсации уже поддерживают явно переданные интервалы; отсутствие таких входов остаётся ограничением реальных данных.
- Месячные отчёты и товары в пути отнесены к складу «Алматы» (нет разбивки по складам).
- Пустые месячные продажи = 0; пустые остатки = «неизвестно».
- Отрицательные транзакции = возвраты (исключены); отрицательный месячный итог ограничен нулём, `raw_qty` сохранён.
- Сроки поставки (IEK 21, Systeme 35 дн) — допущения, требуют подтверждения.
- Устаревшие снимки остатков (фолбэк по началу месяца) помечаются — обновить перед заказом.
- Формулы Excel — по сохранённым значениям; внешние ссылки не обновляются.

Счётчики некорректных/отфильтрованных ячеек — в `Dataset.metadata.counts`.

## 5. Как пересобрать / обновить

До реализации версионированных партий остановите **API и worker**, сохраните предыдущий комплект файлов и замените весь набор по согласованным именам. API также загружает данные для `/meta`; нельзя оставлять его читающим частично заменённый набор. Изменение mtime/размера обновляет кеш, но само по себе не гарантирует согласованность партии.

Проверка в Python 3.12 из корня проекта:

```bash
cd backend
.venv/bin/python -c "from app.data.excel import ExcelDataSource; ExcelDataSource('..').load()"
RUN_REAL_EXCEL_TESTS=1 .venv/bin/python -m unittest tests.test_excel_import -v
```

После успешной загрузки запустите API/worker и проверьте `/api/meta` после входа. Сверьте даты, число SKU/складов, остатки, путь и предупреждения с ожидаемыми значениями нового источника. Не превращайте старые контрольные числа в требование к новому ассортименту.

`DATA_AS_OF=YYYY-MM-DD` фиксирует дату Excel, CSV и synthetic; сроки задаются `IEK_LEAD_TIME_DAYS` / `SYSTEME_LEAD_TIME_DAYS`. Новый расчёт создаёт отдельный постоянный заказ. Старый заказ и экспорт читают свой сохранённый JSON/решения и не пересчитываются из нового набора. Однако checksum/import ID каждого входного пакета ещё не закрепляется в заказе; это требование [ТЗ](ТЗ_платформы.md).

## 6. Передача на продакшн — чек-лист

- [ ] Подтвердить у поставщиков реальные сроки поставки (заменить допущения).
- [ ] Обновить снимок остатков/пути на актуальную дату.
- [ ] Согласовать разбивку по складам (сейчас всё отнесено к «Алматы»).
- [ ] Проверить `warnings` в `/api/meta` после входа; убрать предупреждение только после подтверждения исходных данных, а не ради зелёного статуса.
- [ ] Прогнать тесты импорта на обновлённых данных и регрессионный набор; `validate_must_have` отдельно использует синтетику.
- [ ] Зафиксировать выбранный способ передачи заказа. Если требуется загрузка в 1С, согласовать и испытать обработку конкретной конфигурации; текущий XLSX сам по себе не гарантирует импорт.
- [ ] Проверить целостность новых партий, права пользователей и восстановление заказов/исходников по [DEPLOY.md](DEPLOY.md). Две текущие роли и личное подтверждение строк не закрывают полный процесс согласования ТЗ.

## 7. Отдельный публичный справочник

`data/ekt/catalog.json` содержит описательные данные ekt.kz и сведения о получении. Он не добавляет продажи и остатки, не изменяет единицы, цены, партии и сроки. Внутренняя `category` не подменяется внешней `product_category`.

Зафиксированный снимок EKT содержит 800 записей; применены **773 из 3 907 SKU**, покрытие частичное. В полном контрольном расчёте обогащены 118 из 430 строк. Эти числа характеризуют описания, а не точность прогноза.

Проверяйте `data_quality.catalog_enrichment` в `/api/meta`: состояние файла, источник, дату, число сопоставленных SKU, пропуски и конфликты. Покрытие публичного справочника не является оценкой полноты учётной истории. Контракт и синхронизация — [КАТАЛОГ_EKT.md](КАТАЛОГ_EKT.md); учётный контракт — [ИНТЕГРАЦИЯ_1С.md](ИНТЕГРАЦИЯ_1С.md).

## 8. Производные наборы ветки `alish`

Проверен `baitc/alish` на `5facda2` (`Add new data files for machine learning model training and quality issues`). SHA-256 шести исходников IEK совпали с основной веткой: производные CSV не добавляют новые первичные наблюдения. Они полезны для исследования качества, подготовки признаков и последующего сравнения моделей.

| Каталог | Происхождение и назначение | Использование сервисом |
|---|---|---|
| `scripts/` | Проверенные скрипты и тесты из ветки с локальными исправлениями | Запускаются отдельно |
| `data/clean/iek/` | Результат `clean_monthly_data.py`: месячная очистка и журнал ячеек | Не загружается API |
| `data/ml/iek/` | Результат `prepare_ml_data.py`: панель, признаки, разбиения, сверка и SHA-256 | Не загружается API; производные CSV добавлены в Git коммитом `c7062f9` |

В ML-таблицах сохраняется исходный знак транзакций и неизвестность пустых продаж. Их численность нельзя напрямую сравнивать с положительными транзакциями двух поставщиков в `/api/meta`. Таблицы ML не соответствуют контракту `CsvDataSource`; изменение `DATA_DIR` не подключит их корректно. Количество строк и ограничения: [АУДИТ_ВЕТКИ_ALISH.md](АУДИТ_ВЕТКИ_ALISH.md).

## 9. География исходников

Все непустые складские значения транзакций относятся к Алматы. Месячные матрицы и путь не имеют отдельной складской аналитики: присвоение Алматы — сохраняемое допущение. В ветке `alish` новых городских выгрузок не появилось. Девять городов выбора на сайте зафиксированы как география публичного каталога, а не готовые расчётные склады: [ГОРОДА_И_СКЛАДЫ.md](ГОРОДА_И_СКЛАДЫ.md).


## 10. Демонстрационный CSV и synthetic

[`data/sample_csv/`](../data/sample_csv/README.md) содержит шесть обязательных файлов контракта и `catalog.csv`: продажи, остатки, путь, поставщики, связи SKU, интервалы отсутствия и каталог с единицами м/шт. Это маленький воспроизводимый пример с кодами, сохраняющими ведущие нули. Он не является выгрузкой компании и не расширяет подтверждённую географию.

CSV валидирует колонки, ключи, конечные числа, даты, кратность и единицы. Без `DATA_AS_OF` дата задаётся днём после последней продажи; без истории нужен явный параметр. Synthetic использует фиксированное 2026-09-23 и явные единицы; дату можно переопределить. При смене режима перезапускаются API и worker.

## 11. Результаты исторической оценки

[`data/evaluation/`](../data/evaluation/) содержит `forecast_backtest.json` и `forecast_metrics.csv`: источники/SHA-256, runtime, временной протокол, покрытие, MAE/WAPE/bias по поставщику/единице/политике пропусков. Строки детализации создаются отдельно по `--write-predictions`; отсутствие CSV деталей не означает отсутствие расчёта метрик.

Протокол — [BACKTEST.md](../scripts/BACKTEST.md). Оценены месячные продажи на validation январь–июнь 2026 и test июль–август 2026 без передачи будущего в прогноз. Общего превосходства над предыдущим месяцем не подтверждено. Результаты не являются новыми исходниками заказа, моделью ML, оценкой скрытого спроса или доказательством ROI.

## 12. Постоянные заказы и доступ

SQLite по `APP_DB_PATH` хранит именных пользователей, сессии, задания, неизменяемый результат расчёта, текущие решения/`revision` и события. Менеджер видит свои заказы, администратор — все. Экспорт содержит ID заказа/расчёта и версию; несохранённые правки legacy-клиента отклоняются. База, исходные Excel и конфигурация резервируются раздельно; один Git-репозиторий не заменяет копию текущих рабочих решений. Исторические версии решений и партии входных файлов пока не представлены самостоятельными неизменяемыми сущностями.
