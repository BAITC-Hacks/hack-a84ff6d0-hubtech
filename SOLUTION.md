# Решение · ЭКТ · Автозаказы поставщикам

Сервис автоматического формирования рекомендованных заказов поставщикам для
пополнения склада. Кейс ТОО «Электрокомплект», HackAlem AI (трек 05 · Логистика).
Первоисточник задачи: [relly-problem.md](./relly-problem.md).

## Архитектура

```
backend/  FastAPI + движок расчёта (Python)
  app/
    api/routes.py        REST: /health /meta /recommend /recommend/export
    core/
      outliers.py        MH#4 — исключение разовых оптовых заказов
      stockout.py        MH#3 — компенсация упущенного спроса
      forecasting.py     MH#2 — прогноз: сезонность + тренд
      replenishment.py   MH#1 — базовая потребность (точка заказа + страховой запас)
      recommend.py       оркестратор + MH#5 (группировка по поставщикам)
      explain.py         обоснование строки (OpenAI/Codex или шаблон)
      export.py          экспорт в Excel (совместимость с 1С)
    data/
      adapter.py         абстракция источника (synthetic | csv-1С)
      synthetic.py       генератор реалистичных данных
    schemas.py           контракты (pydantic)
  tests/validate_must_have.py   автопроверка 5 Must-have
```

движка: достаточно положить CSV в `DATA_DIR` и выставить `DATA_SOURCE=csv`.

## Методология расчёта

Для каждого артикула последовательно:

1. **Исключение разовых крупных заказов (MH#4).**
   Оптовые отгрузы одному клиенту искажают регулярный спрос. Транзакция
   помечается как разовая, если её объём одновременно:
   - выше верхней границы Тьюки `Q3 + 3·IQR` (экстремальный выброс) **и**
   - ≥ 8× медианы по артикулу (защита от ложных срабатываний);
   - либо покрывает > 40 % всего объёма по артикулу (концентрация).
   Такие транзакции исключаются из ряда регулярного спроса, число и объём
   исключений сохраняются для объяснимости.

2. **Компенсация упущенного спроса (MH#3).**
   Строится непрерывный дневной ряд спроса. Дни из зафиксированных периодов
   `stockout` замещаются оценкой ожидаемого спроса = базовый уровень (по «здоровым»
   будним дням) × сезонный коэффициент месяца. Суммарный uplift добавляется к
   потребности — расчёт по «сырым» продажам занизил бы её.

3. **Прогноз с сезонностью и трендом (MH#2).**
   Ряд раскладывается на: десезонализированный уровень (среднее по последним 90 дн),
   сезонные коэффициенты по месяцам, линейный тренд (наклон недельного ряда,
   `numpy.polyfit`; статистически совместимо со statsmodels Holt). Прогноз на
   горизонт = уровень × сезонность горизонта × коэффициент тренда.

4. **Базовая потребность (MH#1).**
   Модель точки заказа с покрытием на горизонт `H = срок поставки + период проверки`:
   ```
   потребность = прогноз_спроса(H) + страховой_запас − остаток − товары_в_пути
   страховой_запас = z(уровень сервиса) · σ_дневной · √H
   ```
   Результат округляется до кратности партии и поднимается до минимальной партии
   поставщика. Учитываются ВСЕ источники — изменение любого меняет результат.

5. **Группировка по поставщикам + обоснование (MH#5).**
   Позиции с ненулевой потребностью группируются по поставщику, сортируются по
   срочности. К каждой строке прикладывается прозрачная раскладка и текстовое
   обоснование (LLM при наличии ключа, иначе детерминированный шаблон).

**Срочность:** `high` — покрытие меньше срока поставки; `medium` — меньше горизонта;
иначе `low`.

## Ограничения кейса — как выполнены

- **Не отправляем заказ автоматически** — только рекомендация; утверждение вручную в UI.
- **Данные о клиентах обезличены** — используется только синтетический `client_id`.
- **Объяснимость** — раскладка расчёта + обоснование по каждой строке.
- **Устойчивость к выбросам** — robust-детекция (Тьюки/медиана), а не среднее.
- **Совместимость с 1С** — экспорт плоской таблицы в Excel.

## Запуск

### Backend
```bash
cd backend
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
cp .env.example .env        # ключ OpenAI не обязателен — работает и без него
./.venv/bin/python -m uvicorn app.main:app --port 8017 --reload
```
Docs: http://localhost:8017/docs

### Проверка 5 Must-have
```bash
cd backend
./.venv/bin/python -m tests.validate_must_have
```

### Frontend
```bash
cd frontend
npm install
npm run dev        # http://localhost:5173 (проксирует /api → :8017)
```

### Подключение реальных данных 1С
Выставить в `.env`: `DATA_SOURCE=csv`, `DATA_DIR=./data_1c` и положить туда
`sales.csv, stock.csv, in_transit.csv, suppliers.csv, sku_suppliers.csv,
stockouts.csv` (колонки — как в `app/data/adapter.py::Dataset`).
