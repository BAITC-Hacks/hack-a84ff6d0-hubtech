# Umytpa — заказы поставщикам

Внутренний сервис отдела закупок ТОО «Электрокомплект»: расчёт пополнения по
выгрузкам 1С, проверка обоснований, корректировка и утверждение строк,
сохранение решений сотрудников и экспорт Excel.

Менеджер работает со своими заказами. Администратор управляет сотрудниками
и видит все заказы. Сервис не отправляет заказы поставщику автоматически.
Руководитель согласования, бюджетные лимиты и прямая загрузка в 1С не входят
в текущую версию.

## Возможности

- Расчёт отдельно по артикулу и складу с сезонностью, трендом, остатком,
  ожидаемыми поступлениями, страховым запасом, MOQ и дробной кратностью.
- Месячные итоги — выбранный основной источник объёма до сверки с партнёром; транзакции помогают
  выявить исключительный опт. Точные интервалы отсутствия товара в
  приложенных выгрузках отсутствуют: выдуманного восстановления спроса нет.
- Отдельные фильтры категории 1С и товарной группы ekt.kz. Локальный справочник
  добавляет проверенные описания/характеристики, сохраняя учётные количества.
- Поиск, фильтры, пагинация, исходная рекомендация и решение менеджера,
  отдельные итоги по единицам измерения, обоснования и предупреждения.
- Личные аккаунты, восьмичасовые сессии, сохранённые заказы, версии изменений,
  журнал действий и Excel из сохранённой версии без нового прогноза.
- Постоянная очередь: один расчёт, остальные ожидают; отмена и таймаут
  десять минут. Числовые объяснения работают без внешних сервисов.

## Локальный запуск

Поддерживаемая среда: **Python 3.12**, **Node.js 22.19** (минимум 22.12), npm.
Команды ниже для Linux/macOS; в Windows используется `.venv\Scripts\python.exe`.

```bash
cd backend
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
cp .env.example .env
```

В `backend/.env` явно задайте `APP_ENV=development` для локального HTTP.
Продовая конфигурация использует только HTTPS и защищённые cookie.
Первого администратора создайте без стандартного пароля:

```bash
.venv/bin/python -m app.manage migrate
.venv/bin/python -m app.manage create-admin
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8017 --reload
```

В отдельном терминале из `backend` запустите очередь:

```bash
.venv/bin/python -m app.worker
```

В третьем терминале:

```bash
cd frontend
npm ci
npm run dev
```

Интерфейс — `http://localhost:5173`; Vite направляет `/api` в локальный API.
Исходные `IEK/` и `Systeme electric/` читаются без изменения. Для демонстрации
можно выбрать `DATA_SOURCE=synthetic` в `backend/.env`.

## Проверки

```bash
cd backend
.venv/bin/python -m unittest discover -s tests -v
RUN_REAL_EXCEL_TESTS=1 .venv/bin/python -m unittest tests.test_excel_import -v
.venv/bin/python -m tests.validate_must_have
cd ../frontend
npm test
npm run lint
npm run build
```

Из корня `backend/.venv/bin/python qa/smoke_service.py --real-data` проверяет настоящий API,
отдельный worker, права, сохранение и содержимое обоих листов Excel на
приложенных выгрузках в изолированной временной БД.

Версии Python-зависимостей зафиксированы вместе с транзитивными зависимостями
в `backend/requirements.lock`, JavaScript — в `frontend/package-lock.json`.
CI использует ту же поддерживаемую среду. Успешная сборка сама по себе не
подтверждает готовность: перед вводом нужны сценарии из матрицы приёмки
на реальном API и выгрузках, проверка HTTPS и восстановления копии.

## Данные и поставка

Приложенный набор содержит 3 907 SKU и 248 467 транзакций с датой
моделирования 23.09.2026. Число строк заказа зависит от параметров и версии
источников. Устаревшие остатки и неизвестные условия партии показываются
как допущения, а не скрываются.

Сервис предназначен для одного Linux-сервера и небольшого отдела
(ориентир — до 10 одновременно работающих сотрудников). База SQLite
хранится на локальном диске, ежедневные копии — отдельно от приложения.
Адрес сервера, доверенный TLS-сертификат и доступ задаёт организация.

## Справочник EKT и исследовательские данные

Снимок `data/ekt/catalog.json` применяется только к Excel-источнику. Сеть во
время расчёта и экспорта не нужна. `EKT_CATALOG_ENABLED` включает обогащение,
`EKT_CATALOG_PATH` задаёт отдельный путь к JSON. Отсутствующий/невалидный файл
даёт предупреждение, а числовой расчёт продолжает работать.

Результат ограниченного прохода main от 23.09.2026: 800 карточек, применено
773 из 3 907 SKU (около 19,8%), 9 товарных групп; 200 кодов помещены сборщиком
на ручную проверку, 27 записей отклонены при сопоставлении артикула.
Покрытие частичное и не доказывает доступность товара на складе. Текущие
показатели приходят через API, они не зашиты в интерфейс. После исключения
двух служебных строк пути полный каталог содержит 3 907, а не 3 909 SKU;
реальные товары с кодами `0` и `1` сохраняются.

В репозиторий включены 12 производных CSV и три JSON-отчёта из `data/clean/iek/`
и `data/ml/iek/` для воспроизведения проверки. Скрипты `scripts/` создают их из
тех же IEK-выгрузок; они не добавляют новую историю, другие города или обученную
модель. Формат ML-файлов не соответствует шести CSV рабочего `CsvDataSource`.
По умолчанию неизвестные продажи остаются неизвестными; все 28 979 целей
зафиксированного обучающего набора положительны. Это ограничение будущей оценки,
а не измеренная точность прогноза.

Отдельные тесты подготовки запускаются из корня:

```bash
backend/.venv/bin/python -m unittest discover -s scripts -p 'test_*.py' -v
```

Датированные результаты прежних веток приведены в [ПРИЕМКА.md](docs/ПРИЕМКА.md).
Они не заменяют новый прогон объединённой версии.
