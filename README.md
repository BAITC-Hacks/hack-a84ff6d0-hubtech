## 🎯 Реальная задача (кейс партнёра)

**Партнёр:** ТОО «Электрокомплект» ([ekt.kz](https://ekt.kz))
**Кейс:** Автоматизация формирования заказов поставщикам для пополнения склада.

Сейчас менеджер закупа считает потребность **вручную в Excel** → расчёт редкий, не в реальном времени → избыток по одним позициям, дефицит по другим; разовые крупные заказы искажают регулярную потребность.

**Нужно:** сервис, который формирует **рекомендованные заказы поставщикам** на основе истории продаж, сезонности, устойчивого роста спроса, остатков, товаров в пути, категорий, прогноза прироста и оценки упущенного спроса — и **исключает разовые крупные заказы** (опт одному клиенту).

> ⚠️ Это задача **прогноза спроса + оптимизации запасов** (demand forecasting / inventory replenishment), а НЕ маршрутизация перевозок.

### Вход → Выход
- **Вход:** история продаж (дата, артикул, кол-во, обезличенный клиент, цена, склад, остаток), периоды stockout, справочник поставщиков + сроки поставки, материальная ведомость из 1С.
- **Выход:** список рекомендованных заказов (артикул, поставщик, кол-во, обоснование, срочность), сгруппированный по поставщикам, с экспортом (совместимость с 1С).

### 5 Must-have
1. Базовый расчёт потребности по каждому артикулу (учитывает ВСЕ источники: продажи, остатки, товары в пути, категории, прогноз).
2. Учёт **сезонности** и устойчивого роста спроса (не просто среднее).
3. Оценка и компенсация **упущенного спроса** в периоды stockout.
4. Выявление и **исключение разовых крупных заказов** (в т.ч. опт одному клиенту).
5. Итоговый список, **сгруппированный по поставщикам**, с обоснованием по каждой позиции.

### Ограничения
- ❌ Нельзя авто-отправлять заказ поставщику без подтверждения сотрудника.
- ❌ Нельзя использовать неанонимизированные данные о клиентах.
- ✅ Обязательно: приватность, объяснимость расчёта, устойчивость к выбросам, совместимость выхода с учётной системой.

## 📊 Данные в предоставленных Excel-файлах

| Нужно | Есть? |
|---|---|
| Продажи по датам, документам, артикулам и складу | ✅ импортируются, клиент и цена в динамике отсутствуют |
| Точные периоды stockout | ⚠️ отсутствуют; по месячным остаткам не выдумываются |
| Сроки новых поставок | ⚠️ настраиваемые допущения IEK 21 / Systeme 35 дней |

| Товары в пути | ✅ количество и ожидаемая дата поступления |
| Категории товаров | ⚠️ частично есть у Systeme; остальные отмечены как неизвестные |
| История и сезонность | ✅ месяцы 2024–2026 и коэффициенты поставщиков |
| MOQ / кратность | ✅ с явными предупреждениями о пропусках и ошибках Excel |

## 🔌 Технологический стек (реальный, под эту задачу)

Внешние публичные API (карты/погода/валюты) **не нужны** — задача self-contained на данных.

| Слой | Инструмент |
|---|---|
| Обработка данных | **pandas**, **numpy** |
| Прогноз спроса + сезонность | **Prophet** / **statsmodels** (SARIMA, seasonal_decompose); опц. **LightGBM** |
| Исключение выбросов/опта | IQR / z-score / **Hampel filter** (Must-have #4) |
| Agentic-слой + обоснования | **OpenAI API / Codex** — объяснение по каждой строке заказа (обяз. условие хакатона) |
| Бэкенд | **FastAPI + SQLite** |
| Экспорт для 1С | **openpyxl** / `pandas.to_excel` |
| Дашборд | **React** (или **Streamlit** для скорости демо) |
