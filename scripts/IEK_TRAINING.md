# Обучение месячного прогноза IEK

Только IEK. Скрипт обучает прогноз продаж и проверяет его на прошлых периодах.
Он не меняет алгоритм backend, не формирует утверждённый заказ и не обрабатывает Systeme Electric.

## Запуск

Из корня проекта (Python 3.11 или новее):

```bash
python3 -m venv .venv-ml
.venv-ml/bin/python -m pip install -r scripts/requirements-training.txt
# Если изменились исходные Excel, сначала пересоберите подготовленные данные:
.venv-ml/bin/python scripts/prepare_ml_data.py --as-of 2026-09-23
.venv-ml/bin/python scripts/train_iek_model.py
.venv-ml/bin/python -m unittest discover -s scripts -p 'test_*.py'
```

Дата и горизонт берутся из `config/iek_replenishment.json`: 23.09.2026,
21 + 14 = 35 дней. Источники проверяются по SHA-256 из отчёта подготовки.
Настройки пропусков должны оставаться `missing`, как согласовано с пользователем.
Повторный запуск обновляет только результаты обучения и прогнозов.

## Что сравнивается

1. `mean_3`: среднее известных продаж за 3 календарных месяца. При отсутствии —
   среднее за 6 месяцев, затем среднее всей известной прошлой истории.
2. `seasonal_12`: продажи того же месяца предыдущего года; если неизвестны — первый вариант.
3. `boosting_squared`: общий HistGradientBoostingRegressor с квадратичной функцией потерь.
4. `boosting_poisson`: тот же алгоритм с функцией потерь Пуассона.

Реализация использует [HistGradientBoostingRegressor из scikit-learn](https://scikit-learn.org/1.7/modules/generated/sklearn.ensemble.HistGradientBoostingRegressor.html).
Пропуски признаков передаются как NaN. Случайное внутреннее разбиение для ранней
остановки отключено. Число итераций фиксировано, генератор имеет seed 42.

Для товаров с разными масштабами целевые количества делятся на среднее за прошлые
6 месяцев (при отсутствии — среднее всей прошлой истории; минимум масштаба 1).
После предсказания возвращаются исходные единицы. Модель использует относительные
лаги, средние, вариацию, прошлый остаток, календарную сезонность, отношение средних
за 3 и 6 месяцев, число известных месяцев и единицу измерения. SKU — ключ группировки,
не числовой признак. Изменение названия SKU не задаёт искусственного порядка товаров.

Готовые коэффициенты из Excel, MOQ, поставки и будущие остатки в обучение не включаются.
Модель обучается зарегистрированным продажам: компенсация упущенного спроса и удаление
разового опта здесь не выполняются.

## Временная проверка

- Первоначальная история: до декабря 2025 включительно.
- Validation: январь–июнь 2026; выбор лучшей из четырёх моделей.
- Test: июль–август 2026; оценка уже выбранной модели.

Перед каждым месяцем модель обучается заново только на более ранних месяцах.
Это последовательная проверка на один месяц вперёд: при оценке августа фактический
июль уже доступен. Это не проверка одновременного прогноза на июль и август.
Все модели сравниваются на одних и тех же строках. После тестирования финальные
модели переобучаются на всей доступной завершённой истории до августа включительно.

Победитель определяется по среднему WAPE среди известных единиц измерения с равным
весом каждой единицы. Метры, штуки и упаковки не суммируются. MAE, WAPE и Bias
сохраняются отдельно по единицам, а также по короткой истории и доле неизвестных месяцев.
Отдельно указан охват оценки. Пропуски и отрицательные значения не служат целями:
метрики относятся только к известным неотрицательным продажам. Это создаёт смещение
выборки; качество на неизвестных месяцах и частота нулевого спроса не установлены.
Сохранённые признаки дополнительно сверяются с месячной панелью.

## Результаты

В `data/forecasts/iek/`:

| Файл | Содержание |
|---|---|
| `training_summary.md` | Короткий отчёт, сравнение победителя со средним и ограничения |
| `training_report.json` | Настройки, критерий выбора, охват, версии и контрольные суммы |
| `metrics_by_unit.csv` | MAE, WAPE, Bias отдельно по единицам и периодам |
| `metrics_by_segment.csv` | Ошибки по длине истории и доле неизвестных месяцев |
| `backtest_predictions.csv` | Прогноз, факт, остаточная ошибка и последняя дата обучения каждой строки |
| `monthly_forecast.csv` | Полный прогноз сентября и рекурсивный прогноз октября |
| `horizon_forecast.csv` | Приближённое количество продаж за 35 дней по каждому товару |

В `models/iek/`: по одному `.pkl` на кандидата и `selected_model.pkl` с выбранным
вариантом. Папки моделей и окружения исключены из Git. Артефакты pickle содержат
исполняемые Python-объекты: загружайте только созданные и доверенные файлы.

Чтобы использовать сохранённую модель в Python, импортируйте `predict_model` из
`scripts/train_iek_model.py`, загрузите локальный `selected_model.pkl` через pickle
и передайте подготовленные признаки с `history_mean`. Функция `attach_history`
добавляет это среднее из прошлых месяцев панели. Окружение должно совпадать с версиями
из `training_report.json`; функция прогноза сама не обновляет лаги за новые месяцы.

## Прогноз на 35 дней и дальнейшая интеграция

Период `[23.09.2026, 28.10.2026)` содержит 8 дней сентября и 27 дней октября.
Поэтому приближённая потребность равна `прогноз сентября × 8/30 + прогноз октября × 27/31`.
Прогноз октября использует предсказание сентября в качестве лага. Фактические частичные
продажи сентября не подмешиваются, а прогнозные месяцы не увеличивают число фактически
известных месяцев в выходном отчёте. Товары с менее чем тремя известными прошлыми
месяцами остаются без прогноза (`insufficient_history`), а не с нулевым прогнозом.

Внутримесячная равномерность — допущение. Месячная проверка не доказывает точность
35-дневного горизонта. Для страхового запаса нужен отдельный тест и калибровка ошибок
именно горизонта заказа; сервис 95% текущим результатом не гарантируется.

Следующий этап — проверка прогноза на горизонте заказа, калибровка страхового запаса,
объединение по `sku` с `data/orders/iek/order_inputs.csv`, применение MOQ/кратности и
сортировка по ожидаемой дате дефицита. До получения свободных остатков и правил
пересчёта единиц нельзя выдавать окончательные количества заказа.
