## 1. Контекст и цели продукта

### 1.1. Бизнес-задача кейса
Менеджеры закупа ТОО «Электрокомплект» вручную формируют заказы поставщикам (IEK, Systeme Electric и др.) в Excel.  
**Цель сервиса:** автоматизировать расчёт рекомендованных заказов для пополнения склада на основе математической модели прогноза спроса, исключения оптовых выбросов, компенсации упущенного спроса и расчета страхового запаса.

### 1.2. Ключевые требования (5 Must-have)
1. **Базовый расчёт потребности по каждому артикулу** (учёт продаж, остатков, товаров в пути, категорий, прогноза).
2. **Сезонность и тренд** (прогноз на горизонт с учётом сезонных коэффициентов и динамики роста).
3. **Компенсация упущенного спроса** (оценка потерь в периоды stockout).
4. **Исключение разовых крупных заказов** (детекция аномальных оптовых сделок одного клиента).
5. **Группировка по поставщикам + объяснимость (LLM/шаблон)** каждой позиции с возможностью ручной правки и экспорта в Excel для 1С.

### 1.3. Задача фронтенда
Перевести текущий функциональный табличный прототип в **премиальный, ультра-удобный Mobile-First веб-интерфейс**, строго следуя фирменной дизайн-системе **inDrive** (высокий контраст, неоново-зеленый бренд-акцент, скругленные формы-капсулы, Bottom Sheet шторки, нео-бруталистские скетч-элементы для инфографики).

## 2. Анализ текущего состояния (`frontend/`)

### Что уже реализовано:
- ✅ Базовая интеграция с REST API (`/api/meta`, `/api/recommend`, `/api/recommend/export` в `src/api.js`).
- ✅ Логика валидации количеств, кратности партий (pack_size), минимального заказа (MOQ) и статусов утверждения (`src/orderUtils.js`).
- ✅ Модульные тесты для утилит (`src/orderUtils.test.js` на Vitest/Jest).
- ✅ Прототип отображения групп поставщиков и строк заказов.

### Чего не хватает (проблемы прототипа):
1. **Дизайн и эстетика:**
   - Используется стандартная темная тема с синими акцентами (`#0f1420`, `#4c8dff`), не соответствующая ТЗ inDrive.
   - Нет фирменных шрифтов (Google Fonts: Outfit / Plus Jakarta Sans + Caveat для скетчей).
   - Нет капсульных форм (`border-radius: 999px`) и мягких теней карточек (`border-radius: 24-32px`).
2. **Mobile UX:**
   - Широкая таблица неудобна на мобильных экранах (нет адаптивных карточек с жестами).
   - Отсутствует Bottom Sheet (шторка деталей заказа и обоснования «Почему такой заказ?»).
3. **Визуализация аналитики и объяснимости:**
   - Раскладка `rationale` показана скучным текстом, нет наглядной визуализации формулы потребности (продажи + сезонность + тренд - остаток - путь + страховой запас).
   - Нет спарклайнов/мини-графиков сезонности и динамики.
4. **Интерактивность:**
   - Нет Skeleton Shimmer анимаций во время пересчёта.
   - Нет пульсирующих бейджей для критических рисков дефицита (Urgency = High).

```css
  --primary-green-hover: #A8D500;
  --primary-green-glow: rgba(188, 237, 0, 0.25);
  
  /* Фоны и поверхности */
  --bg-dark: #2A2A2B;               /* Фирменный глубокий тёмный фон */
  --bg-dark-card: #333334;          /* Плашки поверх темного фона */
  --bg-surface-white: #FFFFFF;      /* Карточки, формы ввода, белые плашки */
  --bg-promo-light: #FBFBEA;        /* Мягкий бежево-желтый для блоков статистики */
  --bg-selected-blue: #E5F2FF;      /* Подсветка активного элемента */
  --accent-blue: #3A75DF;           /* Синий акцент: точка маршрута, метки */
  
  /* Текст и состояния */
  --text-main-black: #000000;       /* Текст на белом или салатовом */
  --text-main-white: #F5F5F7;       /* Текст на тёмном фоне */
  --text-muted: #9E9E9E;            /* Второстепенные подписи */
  --danger-red: #FF3B30;            /* Высокая срочность / дефицит */
  --warning-orange: #FF9500;        /* Средняя срочность */
  --rating-yellow: #F3CE33;         /* Рейтинги, акцентные звёзды */

  /* Формы и радиусы (Bubble / Capsule) */
  --radius-pill: 999px;             /* Кнопки, инпуты, фильтры */
  --radius-card: 24px;              /* Карточки, панели */
  --radius-modal: 28px 28px 0 0;    /* Bottom Sheet шторка */
  --radius-tag: 12px;               /* Мелкие чипы */

  /* Тени */
  --shadow-card: 0 4px 20px rgba(0, 0, 0, 0.08);
  --shadow-floating: 0 10px 30px rgba(0, 0, 0, 0.25);
}
```

### 3.2. Типографика
- **Основной UI:** `Plus Jakarta Sans` / `Outfit` (веса 400, 500, 600, 700).  
  Крупные плотные заголовки (`letter-spacing: -0.02em`), капсульные кнопки жирным начертанием.
- **Скетч и промо-акценты:** `Caveat` / `Permanent Marker`  
  Используется для рукописных пометок в инфографике, бейджей "AI Driven", пометок экономии и дефицита.

## 5. Детализация ключевых пользовательских сценариев (UX)

### 5.1. Экран 1: Верхняя панель и сводка (Summary Deck)
- **Логотип в стиле inDrive:** яркий неоново-зеленый шильдик `iD · Logistics` с девизом *"Replenish driven"*.
- **Индикатор источника данных:** чип со статусом `🟢 1С Excel (IEK, Systeme Electric)` или `🟡 Synthetic`.
- **4 Neo-Brutalist инфо-карточки** (белый фон, черная рамка 2px, скетчевый зеленый хайлайтер):
  1. *Поставщиков:* активное количество (напр., 2).
  2. *Позиций к заказу:* общее число SKU с ненулевой потребностью.
  3. *Критический дефицит:* бейдж с пульсирующей точкой (покрытие < срока поставки).
  4. *Утверждено:* прогресс согласования менеджером (напр., `12 / 430 поз.`).

### 5.2. Экран 2: Панель фильтров и параметров расчёта
- Капсульные выпадающие списки (Склад: «Все» / «Алматы» / «Астана»; Категория: «Все» / «Автоматика» / «Кабель»).
- Быстрый переключатель уровня сервиса (пилюли: `90%`, `95%`, `98%`, `99%`).
- Тоггл `LLM-обоснования` со значком искры/AI.
- Главная кнопка действия (Primary CTA): ярко-салатовая капсула `«Рассчитать заказ»` с анимацией нажатия.

### 5.3. Экран 3: Интерактивный список заказов по поставщикам
- **Свайпер поставщиков:** удобное горизонтальное переключение между IEK и Systeme Electric.
- **Карточка позиции (Mobile View & Desktop View):**
  - Верхняя строка: Артикул (моноширинный шрифт) + Наименование + Категория.
  - Средняя строка: Срок покрытия (`Дней запаса: 4 дн` — красный при дефиците) + Кратность упаковки (`кратность 10`).
  - Нижняя строка: Инпут количества (капсула, автопроверка MOQ), чекбокс утверждения, кнопка «Почему?» (лупа/раскладка).

### 5.4. Экран 4: Шторка «Почему такой заказ?» (Rationale Bottom Sheet)
- Открывается по клику на карточку или кнопку «Почему?».
- Поддерживает жест свайпа вниз для закрытия.
- **Интерактивная диаграмма/формула:**
  $$\text{Заказ} = \underbrace{\text{Прогноз}}_{\text{тренд + сезонность}} + \underbrace{\text{Упущенный спрос}}_{\text{компенсация stockout}} + \underbrace{\text{Страховой запас}}_{\text{сервис 95\%}} - \underbrace{\text{Остаток}}_{\text{на складе}} - \underbrace{\text{В пути}}_{\text{ETA}}$$
- **Блок аномалий:** подсвечивает исключенные разовые оптовые заказы (Must-have #4).
- **AI-обоснование:** краткий текст от LLM с человекопонятным объяснением причин заказа.

### 5.5. Экран 5: Экспорт и финальное утверждение
- Закрепленный мобильный док (Bottom Dock):
  - Кнопка 1: `«Выгрузить все с правками»` (Ghost capsule).
  - Кнопка 2: `«Экспорт утверждённых в 1С»` (Primary Green capsule).
- Автоматическая валидация: если менеджер ввёл некорректное число (не кратно партии или меньше MOQ), кнопка блокируется с подсказкой.

## 7. Критерии готовности (Acceptance Checklist)

- [ ] Интерфейс полностью адаптирован под смартфоны (375px+) и ноутбуки.
- [ ] Палитра строго соответствует inDrive: неоново-зеленый `#BCED00`, темный `#2A2A2B`, бежевый `#FBFBEA`.
- [ ] Все кнопки и поля ввода имеют форму капсул (`border-radius: 999px`).
- [ ] Шторка деталей заказа открывается плавно и отображает полную раскладку Must-have (прогноз, упущенный спрос, опт, остатки).
- [ ] Кнопки экспорта скачивают валидный Excel-файл для 1С без перезагрузки страницы.
- [ ] Прогон тестов `npm test` и `oxlint` проходит без ошибок.
