# Umytpa — рабочее пространство закупок ЭКТ

React 19 + Vite 8, нативный fetch, oxlint. Интерфейс реализует требования [фронтенда](../docs/ФРОНТЕНД.md), [дизайн-системы](../docs/Дизайн_фронтенда.md) и внутреннего сервиса: вход сотрудников, сохранённые заказы, история, ручное утверждение и Excel.

## Локальный запуск

Node.js 22.12+; проверено на 22.19. Backend требует Python 3.12 и отдельный worker.

В папке backend установите зависимости, настройте .env по .env.example. Для локального HTTP явно установите APP_ENV=development; в production используется HTTPS. Создайте администратора (пароль запрашивается скрыто):

```sh
python -m app.manage migrate
python -m app.manage create-admin --username admin
```

В двух терминалах из backend:

```sh
python -m uvicorn app.main:app --host 127.0.0.1 --port 8017
python -m app.worker
```

Из frontend:

```sh
npm ci
npm run dev
```

Откройте http://localhost:5173. Vite проксирует /api на http://127.0.0.1:8017. Для другого адреса backend задайте API_PROXY_TARGET при запуске Vite. Без работающего worker расчёт не запускается; интерфейс показывает ответ сервиса. Реальные данные не заменяются демоданными.

## Экраны и права

- **Заказы** — история, архив и серверная пагинация. Менеджер видит свои заказы, администратор — заказы всей команды.
- **Рассчитать** — параметры из справочников, значения по умолчанию от сервера, ограничения данных и состояние фоновой задачи. Повтор запуска после неопределённого сетевого ответа использует тот же ключ идемпотентности. После завершения нажмите «Открыть заказ».
- **Заказ** — поиск по коду 1С, артикулу поставщика, названию или складу; фильтры срочности/поставщика, числовое обоснование, корректировка, утверждение, экспорт и журнал действий.
- **Команда** — реальные учётные записи, создание сотрудника, роль admin/manager, включение/отключение и смена пароля. Раздел доступен администратору.
- **Учётная запись** — текущий пользователь, его роль и выход.

Адреса #/orders, #/calculate?job=ID и #/orders/ID можно сохранять и открывать повторно. Доступ проверяет сервер. Самостоятельной регистрации и автоматической отправки заказов поставщикам нет.

Архивный заказ доступен для просмотра и экспорта. Чтобы менять количества,
утверждения или название, сначала нажмите «Вернуть в работу». Архивирование
сохраняет заказ; удаления через интерфейс нет.

## Сохранение решений

Корректные правки автоматически сохраняются через одну секунду бездействия. Запросы выполняются последовательно и используют последнюю подтверждённую сервером ревизию. Введённое пустое/ошибочное количество остаётся локально; остальные корректные решения сохраняются.

Изменение количества снимает утверждение. Нажатие «Утвердить» сначала сохраняет новое количество, затем отдельным запросом фиксирует утверждение. Ноль исключает строку из заказа, сохраняя отображение риска дефицита. Штуки, метры и другие единицы не складываются между собой.

При конфликте ревизий автосохранение останавливается: показаны локальная и серверная версии. Можно принять серверную версию либо явно перенести только свои изменённые поля. Старое утверждение не переносится на количество, изменённое другим сотрудником.

При завершении сессии незаписанные правки остаются в памяти страницы. Повторный вход того же сотрудника позволяет продолжить; вход другого сотрудника очищает предыдущий черновик. Пароли, токены сессии и решения не записываются в localStorage/sessionStorage. Перезагрузка восстанавливает серверную версию; незавершённый ввод в полях после перезагрузки теряется, о чём браузер предупреждает при наличии таких правок.

Экспорт доступен после сохранения и исправления ошибок. Выгружается сохранённая ревизия: черновик либо положительные утверждённые строки. Поиск, фильтры и страницы не ограничивают утверждение поставщика и экспорт. Серверный журнал показывает автора, время и изменения решений.

## Доступность и оформление

Тёмная оболочка, белые панели, салатовый акцент, основная типографика 16–18 px и вторичная 12–14 px. Golos Text и Caveat поставляются локально через фиксированные версии fontsource; внешних запросов к Google Fonts нет. Лицензии находятся в public/licenses и копируются в сборку.

Поддержаны клавиатура, видимый фокус, подписанные поля, сообщения для скринридеров и prefers-reduced-motion. Обоснование открывается в native dialog с Escape и возвратом фокуса; на телефоне это нижняя панель со свайпом вниз для закрытия. Таблицы прокручиваются горизонтально внутри подписанных областей; область касания чекбоксов увеличена.

## Проверки и сборка

```sh
npm test
npm run lint
npm run build
```

npm test выполняет unit-тесты API и чистых утилит, затем компонентные/интеграционные тесты Vitest + Testing Library в jsdom. Покрыты валидация ответов, безопасные ошибки, Excel, сериализация сохранений, повторный вход, конфликты версий, двухэтапное утверждение, страницы, фокус и жизненный цикл задач.

Production-сборка находится в dist. Статика и /api должны обслуживаться с одного HTTPS-origin. Развёртывание через nginx и systemd, первичная настройка, резервные копии и smoke-проверки описаны в [DEPLOY.md](../docs/DEPLOY.md). Запуск vite preview предназначен для проверки сборки и сам по себе не настраивает API proxy.

## Структура

- src/App.jsx — восстановление сессии, навигация и оболочка приложения.
- src/pages/ — история, расчёт, рабочий заказ, вход и управление сотрудниками.
- src/components/ — таблицы, обоснование, источники данных и общие состояния.
- src/hooks/useOrderEditor.js — локальный ввод, последовательный autosave, конфликт ревизий и повторный вход.
- src/api.js — API, CSRF, ограничение ожидания, отмена и проверка контрактов/Excel.
- src/orderState.js и src/orderUtils.js — решения, согласование версий, валидация и итоги.
- src/test/ — компонентные и интеграционные проверки без реальных учётных данных.
