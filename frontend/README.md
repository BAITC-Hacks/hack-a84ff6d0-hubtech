# Интерфейс Umytpa

React/Vite-клиент закупочного сервиса из `baitc/frontend`, коммит `5a0ace2`: тёмная оболочка, светлые панели, лаймовые действия, локальные Golos Text и Caveat. В интеграции добавлены фильтр/описания EKT, безопасные ссылки и мобильные карточки позиций.

Работают вход, история, фоновые расчёты, серверное сохранение с ревизиями, конфликты, аудит, Excel и управление командой. Роли — **`manager` и `admin`**. Отметка `approved` сохраняет решение по строке; независимое согласование всей версии руководителем пока не реализовано.

## Запуск

Нужен Node.js **22.19+ в ветке 22.x или 24.x**. Из этой папки:

```bash
npm ci
npm run dev
```

Vite слушает `5173`, передаёт `/api` FastAPI на `127.0.0.1:8017`; другой локальный адрес задаётся через `API_PROXY_TARGET`. Сервер, worker и начальный администратор запускаются отдельно по [README](../README.md) и [DEPLOY.md](../docs/DEPLOY.md). Без сессии показывается вход; встроенных логина/пароля и обхода авторизации нет.

## Страницы

| Адрес / состояние | Назначение |
|---|---|
| Нет сессии | Вход / повторный вход; отдельного `#/login` нет |
| `#/orders` | Свои заказы менеджера / все заказы администратора, работа и архив |
| `#/calculate` | Параметры, источники/ограничения, запуск и последние задания |
| `#/calculate?job=ID` | Состояние задания, отмена, переход к результату |
| `#/orders/ID` | Правки/отметки строк, обоснования, конфликт, Excel и журнал |
| `#/users` | Команда — для администратора |
| `#/account` | Имя, роль, статус, выход |

## Данные и сохранение

- Корректные правки сохраняются автоматически с серверным подтверждением; новое количество снимает отметку строки.
- Незавершённый ввод остаётся в памяти страницы. Перезагрузка восстанавливает подтверждённые сервером решения.
- Excel использует сохранённый заказ и ревизию; поиск/пагинация не ограничивают файл, нулевые количества исключаются.
- Склады приходят из `/api/meta`, сейчас реальные данные — Алматы. Города EKT не заменяют склады: [география](../docs/ГОРОДА_И_СКЛАДЫ.md).
- Категория 1С и группа EKT раздельны; покрытие видно, все группы сохраняют товары без описания сайта.
- «Почему?» содержит расчёт, ограничения, характеристики и проверенную HTTPS-ссылку EKT. Сайт не подтверждает запас, цену или срок.
- AI-обоснования выключены по умолчанию, зависят от возможности сервера; числа и шаблоны работают без LLM. CSV `alish` не являются обученной моделью.

До 767 px позиции становятся карточками с теми же полями: по 5 на страницу поставщика, на большем экране — по 20. Размер страницы реагирует на viewport; итоги, решение по поставщику и Excel не ограничиваются видимой страницей. Локальные шрифты не требуют внешнего сервиса; лицензии — в `public/licenses/`.

## Проверки

```bash
npm run test:unit
npm run test:ui
npm run lint
npm run build
npx playwright install chromium
PYTHON=/absolute/path/to/python npm run test:e2e
PYTHON=/absolute/path/to/python npm run test:e2e -- --real-data
```

Укажите Python из окружения с backend-зависимостями. `npm test` объединяет unit- и компонентные тесты; Playwright E2E запускается отдельно. Наличие сценария не означает, что он прошёл: актуальный результат — в [отчёте по критериям](../docs/ОТЧЁТ_ПО_КРИТЕРИЯМ.md).

Реальное поведение — [ФРОНТЕНД.md](../docs/ФРОНТЕНД.md), оформление — [дизайн](../docs/Дизайн_фронтенда.md). [ТЗ](../docs/ТЗ_платформы.md) и [контракт интерфейса](../docs/ИНТЕРФЕЙС_ПЛАТФОРМЫ.md) отдельно определяют целевые пять ролей, десять экранов, области доступа и независимое согласование.
